## ٢. §٣.٤ — التطابق: ملف واحد مختلف

الفحص على `{app, config, routes, database, bootstrap}` بدون `bootstrap/cache`: **٣٤٥ ملف**، منهم **٣٤٤ متطابقين** حرف بحرف مع التاج.

**المختلف:** `database/factories/UserFactory.php`

```
على الإنتاج   2d5a474a…   مؤرخ 29 يونيو   'phone' => '+9665'.numerify('########')
في التاج      e80fd4f4…                    'phone' => '+966555'.numerify('9#####')
```

**التشخيص:** ده **مش تعديل على السيرفر**. ده ملف **ما اتنشرش أصلاً**: النسخة اللي على الإنتاج أقدم، والأحدث هي اللي في الفرع (اتغيّر لما اكتشفنا إن الـfactory القديم بيولّد أرقام سعودية **حقيقية** ممكن تكون بتاعة ناس، والمجموعة وصلت لبوابة SMS مرة يوم 06/09).

**خطورته على الإنتاج: صفر.** الـfactories بتتنادى من `db:seed` والاختبارات وبس — و`::factory()` **مش مستعملة في ولا ملف** جوّه `app/` (متحقَّق بـgrep). والإنتاج ما بيشغّلش لا سيدر ولا اختبارات.

**المقترح:** نضيف الملف للقائمة، فتبقى **٧٠ ملف** بدل ٦٩، والإنتاج يتطابق مع التاج بالكامل. سطر واحد في القائمة، ومكسبه إن الفحص الجاي يرجع «صفر فرق» بدل ما نفتكر الاستثناء ده تاني.

### ٦.١ قرار ١ · `QUEUE_CONNECTION`

مسحنا السطر المكرر. وبفحص مباشر على النسخة:

```

**وحاجة زيادة لقيناها وإحنا بندوّر:** `.env` الإنتاج فيه **أربع مفاتيح مكررة**، مش واحد:

```
CACHE_STORE      سطر 42 = file      سطر 104 = file       ← نفس القيمة، بلا ضرر
FILESYSTEM_DISK  سطر 39 = public    سطر 107 = public     ← نفس القيمة، بلا ضرر

## ٧. 🔴 العيب اللي مسكته البروفة — ملف علامة الإنتاج ناقص

أول ما شغّلنا الأمر المجدول الجديد على النسخة:

```
$ php artisan complaints:reconcile-refunds --alert
⚠ production marker missing: /var/www/.mamsa-production
No refunds pending beyond 6h.
```

**الحقيقة على الإنتاج:** الملف **مش موجود**:

```
ls ~/domains/api.mamsaa.com/.mamsa-production   →   No such file or directory
```

### إيه اللي بيحصل بعد النشر

الملف ده حاجتان مختلفتان:

1. **حارس تشغيل** في `AppServiceProvider`: لو الملف موجود و`APP_DEBUG=true`، التطبيق **يرفض يقلع** — لأن صفحة الخطأ بتعرض كل الأسرار المحمّلة. الملف ناقص = الحارس ده **مش موجود** دلوقتي.
2. **فحص ساعي** في الأمر الجديد: `APP_ENV=production` والملف ناقص → `ProductionMarkerMissing`.

والتنبيه ده بيروح لـ`COMPLAINTS_ALERT_RECIPIENTS` — **وهو غير مضبوط على الإنتاج**، فبيرجع للافتراضي: **كل superadmin نشط**، وده حالياً حساب واحد. **من غير أي تهدئة.** يعني الأمر بيشتغل **كل ساعة**، والنتيجة **إيميل كل ساعة، ٢٤ إيميل في اليوم**، أول ما النشرة تنزل.

### الحل — أمر واحد

```bash
touch ~/domains/api.mamsaa.com/.mamsa-production
```

**مُختبر على النسخة:** بعد إنشاء الملف، الأمر اشتغل نضيف من غير تنبيه، والتطبيق فضل بيخدم عادي (`APP_DEBUG=false` على الإنتاج، فحارس الرفض مش هيوقف حاجة).

ومكسب زيادة: الحارس الأول يبقى فعّال — فلو حد ضبط `APP_DEBUG=true` على الإنتاج بالغلط، التطبيق يرفض يقلع بدل ما يسرّب كلمة القاعدة والمفتاح لأول واحد يشوف صفحة خطأ.

**الشرط ده يتنفّذ مع خطوة `.env` (الخطوة ٣ في الخطة).**

**اقتراحنا:** نعمله على الإنتاج ونحذفه بعده فوراً بـ`id` محدد، ونبعتلكم الرقم قبل وبعد. البديل إننا ما نعملوش ونعتمد على البروفة — وإحنا **مش** مرتاحين للبديل ده، لأن الفحص ده بالظبط هو اللي مسك عيب 22/09.

**قولوا: نعمله ونحذفه، ولا نسيبه؟**

## ١٠. نظافة

- النسخة المؤقتة والحاوية **محليّة عندنا**، وفيها **صورة من بيانات الإنتاج ومن `.env`** بأسراره. هتتمسح بعد النشر.
- على السيرفر: `~/rehearsal/prod-2026-09-27.sql` و`~/rehearsal/app_core-2026-09-27.tgz` — **دول نسخة الرجوع بتاعة §٣.٥**، فسايبينهم عن قصد.
- **ولا إيميل ولا SMS ولا نداء لميسر طلع من البروفة** — `log` و`log` ومفاتيح وهمية.
- خلال البروفة كلها: **خطأ واحد** في السجل، وهو رفض متوقع من فحص عملته أنا (تعديل وحدة قيد المراجعة).

## ١٢. التأكيدات اللي طلبتوها — الأربعة، بدليل حقيقي

كل واحد تحت **مأخوذ من تشغيل فعلي**، مش من الكود ولا من الاختبارات.

### ١٢.١ `unit_id` و`body` و`href` في إشعار `permit_expiring` — ✅ staging

خلّينا تصريح الوحدة 68 ينتهي بعد **٣٠ يوم بالظبط** (عتبة حقيقية من عتبات الجوب: 60/30/14/7/1 ويوم الانتهاء)، ومسحنا سجل التذكير، وشغّلنا الجوب:

```
$ php artisan permits:check-expiry
permit reminders: 1 sent, 0 skipped
notifications: 144 -> 145
```

والصف اللي اتكتب في `notifications`، حرف بحرف:

```json
{
  "type": "permit_expiring",
  "permit_id": 38,
  "threshold": 30,
  "expires_at": "2026-10-27",
  "unit_id": 68,
  "unit_name": "مبنى وضع أ — خطوة واحدة",
  "title": "تصريح وحدتك \"مبنى وضع أ — خطوة واحدة\" ينتهي خلال 30 يوم",
  "body": "لا يمكن استقبال حجوزات تنتهي إقامتها بعد 2026-10-27.",
  "href": "/units/68/permit/renew"
}
```

**التلاتة موجودين.** و`href` بيبقى `null` في إشعار قديم مش شايل `unit_id` — مش بيختفي.

### ١٢.٢ `apartment_no` في `booking.unit` — ✅ staging، بقيمة حقيقية مش `null`

حجزنا على وحدة **جوّه مبنى** (الوحدة 57، الشقة رقم «1» في مجموعة):

```
POST /api/v1/bookings          → 201   id=88
GET  /api/v1/bookings/88       → 200
booking.unit = { "id": 57, "apartment_no": "1" }      ← موجود، وبقيمة
الصف نفسه: bookings.unit_id = 57
```

والقائمة العامة في نفس اللحظة:

```
listing item carries apartment_no: no (correct)     group_size=1     keys=33
```

**المفتاح في رد الحجز، وغايب من القائمة.** (وعلى نسخة الإنتاج نفس الشيء بـ`apartment_no: null` — لأن الوحدة هناك مستقلة، فالمفتاح موجود وقيمته فاضية، وده الصح.)

حجز التأكيد #88 **اتمسح** بعد القراءة.

### ١٢.٣ `permitAddress` في كتابة الوحدة — ✅ اللوحتين

**لوحة الأدمن** — على **نسخة الإنتاج**، الوحدة 35 (الفحص ٤ب و١٣):

```
PATCH /admin/units/35
{ "tourismLicenseNumber": "50047139", "permitAddressCity": "الرياض",
  "permitAddressDistrict": "النرجس", "permitExpiresAt": "2027-12-31" }
→ 200
permitAddress = {"city":"الرياض","district":"النرجس","building":"7","unitNo":null}
permitExpiresAt = "2027-12-31"     permitStatus = "valid"
```

**لوحة الشريك** — على staging، الوحدة 68:

```
PATCH /units/u_68
{ "permitAddressCity": "الرياض", "permitAddressDistrict": "النرجس",
  "permitAddressBuilding": "12", "permitAddressUnitNo": "1",
  "permitExpiresAt": "2028-01-31" }
→ 200
permitAddress = {"city":"الرياض","district":"النرجس","building":"12","unitNo":"1"}
والمخزَّن على صف التصريح: city=الرياض · district=النرجس · expires=2028-01-31
```

**ملاحظة للواجهة:** الوحدة اللي حالتها `pending` بترفض التعديل بـ**`409 UNIT_LOCKED`** — لقيناها وإحنا بنجرّب. مش حاجة جديدة، بس لازمة في الشاشة: زرار الحفظ يتقفل والوحدة قيد المراجعة.

**مفاتيح الكتابة مسطّحة** (`permitAddressCity` …) و**القراءة مجمّعة** (`permitAddress: { city, district, building, unitNo }`).

### ١٢.٤ شكل رد `/config` — ✅ الشكل النهائي

على **نسخة الإنتاج**، التلات مسارات، من غير مصادقة، رد متطابق حرف بحرف:

```
GET /api/v1/config    → 200
GET /config           → 200
GET /admin/config     → 200
```

```json
{
  "flags": {
    "multiUnitEnabled": false,
    "permitExpiryRequired": false,
    "legacyUnitWritesEnabled": false
  },
  "permitWarningDays": 30
}
```

**دي قيم الإنتاج** — مقروءة من نسخته هو، مش من staging (على staging `multiUnitEnabled: true`).

`permitWarningDays: 30` هو **نفس الرقم** اللي الجوب في ١٢.١ اشتغل بيه. ده الغرض من إرساله: عتبة واحدة، مش تلاتة مكتوبين بالإيد في تلات تطبيقات.

**الشكل مستقر** — مفتاحان على المستوى الأول (`flags` و`permitWarningDays`)، وتلات أعلام جوّه `flags`. أي عَلَم جديد بيتزاد جوّه `flags` ومش بيغيّر الشكل.
