الموافقة وصلت والتنفيذ خلص. **والشرطان مش ملاحظات اتسجّلت — دول كود ومختبرين.**

## ١. الشرط الأول — نقطة كتابة واحدة · ✅ **حاجز مش عُرف**

طلبكم كان: «ممنوع أي `->update(['license_type' => …])` مباشر». **العُرف مش كفاية، فعملناها حاجز.**

`Unit::updating` بيرفض أي تعديل بيلمس العمودين إلا لو `UnitLicense` هي اللي بتكتب:

```php
static::updating(function (self $unit) {
    if (UnitLicense::isWriting()) return;
    if ($unit->isDirty(['license_type', 'licensed_units_count'])) {
        throw new \LogicException(
            'license_type/licensed_units_count are group-wide — '.
            'write them through UnitLicense::applyToGroup().'
        );
    }
});
```

**بيرمي مش بيتجاهل.** الكتابة اللي بتتجاهل في صمت أسوأ من اللي بتفشل — اللي كتبها هيفتكر إنها اتحفظت.

**الإنشاء مستثنى بقصد:** الصف الجديد مجموعة من واحد، والـ cloner بينسخ من المصدر اللي بينسخه — فمفيش طريق منهم يقدر يعمل تعارض أصلاً.

### وحد الحاجز — بنقوله صريح

**الحاجز ده مابيشوفش `Unit::where(...)->update(...)`.** الـ query builder مابيشغّلش أحداث الموديل خالص.

وده مش نقص في التنفيذ — **ده بالظبط سبب إن شرطكم التاني ضروري**. الحاجزان بيمسكوا غلطتين مختلفتين:

| الغلطة | اللي بيمسكها |
|---|---|
| `$unit->update([...])` على شقة واحدة (الغلطة المحتملة) | **الموديل** — استثناء فوري |
| `Unit::where(...)->update([...])` (اللي بيعدّي الأحداث) | **الفحص اليومي** |

## ٢. الشرط التاني — الفحص الدوري · ✅ **منفّذ ومجدول**

```
units:check-licenses [--alert]
كل يوم 03:00 بتوقيت الرياض
```

بيستخدم الاستعلام اللي كتبتوه بالظبط، وبيبعت تنبيه عبر نفس مسار تنبيهات العمليات (`OpsAlert` — نفس مستقبلي تنبيهات الاسترداد، مع الرجوع لكل `SuperAdmin` نشط لو القايمة فاضية).

**وبيرجّع exit code غير صفر** لما يلاقي تعارض، عشان أي scheduler أو CI يتعامل معاه كعطل مش كسطر في لوج.

**أول تشغيل على staging:**

```
$ php artisan units:check-licenses
Every building agrees with itself.
exit=0
```

### الاختبارات اللي طلبتوها — **الاتنين موجودين، وواحد زيادة**

| الاختبار | الحالة |
|---|---|
| تعديل التصريح على شقة → كل الصفوف اتغيرت | ✅ (كان موجود من الجولة اللي فاتت) |
| كتابة مباشرة على صف واحد → مرفوضة | ✅ **الموديل بيرمي `LogicException`** |
| الفحص بيمسك التعارض | ✅ **والتعارض متعمول بالـ query builder** — الطريقة الوحيدة اللي الحاجز مابيشوفهاش |
| منصة سليمة → الفحص بيعدّي | ✅ عشان الفحص ما يبقاش بيصرخ دايماً |
| التنبيه بيتبعت | ✅ |
| تعديل عادي (سعر) لسه بيتحفظ | ✅ **الحاجز ما يتحوّلش لـ «الوحدات مش بتتعدّل»** |

> اختبار «الفحص بيمسك التعارض» **بيفتعل التعارض بـ `Unit::where(...)->update()`** بقصد. لو افتعلناه بـ Eloquent، الحاجز كان هيمنعه والاختبار كان هيبقى بيختبر الحاجز مرة تانية بدل ما يختبر الفحص.

| القواعد الأربعة على التوسيع | ✅ **بتتفحص قبل أي كتابة** — التوسيع المرفوض ما بيسيبش شقق ورا |

### كود إضافي مش في المواصفة

`LICENSED_UNITS_COUNT_NOT_APPLICABLE` — تصريح ضيافة خاصة مع عدد أكبر من ١. القيمة دي إما بلا معنى أو الشريك فهم الفورم غلط، **وتجاهلها في صمت بيخليه فاكر إن فيه حد مطبّق وهو مش موجود**.

## ٤. 🟠 أثر عملي لازم تعرفوه

**المجموعات القائمة اللي تصريحها `NULL` مش هتقدر:**

1. **تتوسّع** — `MULTI_UNIT_REQUIRES_FACILITY_LICENSE`
2. **تتعتمد بعد أي تعديل** — لأن FR-066 بيرجّع الوحدة المعدّلة لـ `pending`، والاعتماد بيمر على الحارس

**ده السلوك المقصود** — «`NULL` مش إذن، ده معناه محدش راجع». بس هو **تغيير سلوك حي** ولازم يتقال.

| البيئة | الأثر |
|---|---|
| **الإنتاج** | ✅ **صفر** — مفيش أي مجموعة على الإنتاج |
| **staging** | مجموعة واحدة (٥ وحدات، «برج تجريبي - مبنى كامل») |

مفيش وحدة `pending` وقت النشر، فمحصلش بلوك فعلي. **بس البنش كان هيقف**، فصنّفنا المبنى التجريبي:

```
tourist_facility · licensed_units_count = 8 · حجم المجموعة الحالي = 5
```

اتكتبت عبر `UnitLicense::applyToGroup()` مش SQL مباشر. والرقم ٨ مقصود: **بيخليكم تجربوا المسارين** — التوسيع لـ ٨ بينجح، والمحاولة لـ ٩ بترجّع `QUANTITY_EXCEEDS_LICENSED_UNITS`.

> **ده بيانات اختبار صناعية** («برج تجريبي») وقابل للرجوع لـ `NULL`. **البيانات الحقيقية بتفضل `NULL`** — التخمين هيعلّق ادعاء قانوني على صفوف محدش بصّ عليها.

## ٥. الحقول اللي بتوصل للواجهات

### لوحة الشريك — `GET /api/v1/partner/units/{id}`

جوّه الكتلة الخاصة بالمالك:

```json
{ "license_type": "tourist_facility", "licensed_units_count": 8 }
```

الاتنين `null` لأي وحدة ما اتصنّفتش. **مش في المغلّف العام للضيف** — التصريح شأن الشريك والمراجع.

### لوحة الأدمن — شاشة المراجعة

```json
{ "licenseType": "tourist_facility", "licensedUnitsCount": 8, "groupSize": 5 }
```

**التلاتة مع بعض بقصد.** النظام أصلاً بيرفض مجموعة أكبر من العدد المعلن، فشغل المراجع **مش** على الحجم — شغله على **صدق الرقم المُدخل**: يطابق `licensedUnitsCount` مع الرقم المكتوب في ملف التصريح المرفوع. ده مستحيل من غير ما الشاشة تعرض التلاتة في نفس المكان.

### أكواد الرفض

| الكود | متى |
|---|---|
| `LICENSED_UNITS_COUNT_REQUIRED` | سياحي من غير عدد |
| `LICENSED_UNITS_COUNT_NOT_APPLICABLE` | خاص بعدد > ١ |
| `MULTI_UNIT_REQUIRES_FACILITY_LICENSE` | توسيع بتصريح خاص أو `NULL` |
| `QUANTITY_EXCEEDS_LICENSED_UNITS` | الحجم > العدد المرخّص · `meta.licensed_units_count` |
| `LICENSE_DOWNGRADE_BLOCKED_BY_QUANTITY` | تنزيل التصريح والمبنى لسه قايم |
| `MULTI_UNIT_DISABLED` | الفلاج مقفول |

كلهم `422` بالشكل `{success, message, code, meta}`.

## ٦. البنود المسجّلة عندنا

| البند | الحالة |
|---|---|
| جدول `unit_groups` | 📋 **مسجّل** — ويتقيّم **مع** الاعتماد الجماعي، مش لوحده. لو اتعمل، الحقلين بينتقلوا ليه والفحص الدوري يتشال |
| الاعتماد الجماعي + SLA للمجموعة | 📋 المرحلة الجاية |
| قياس المهلة | 📋 توزيع (إنشاء → نجاح الدفع) للحجوزات الناجحة، p50/p90/p95 · **تاريخ المراجعة يتحط في التقويم يوم النشر على الإنتاج** |

**ملاحظة على `unit_groups`:** ربطكم بينه وبين الاعتماد الجماعي هو الجزء المهم في البند. الاعتماد الجماعي محتاج **حالة للمجموعة** و**SLA للمجموعة** — والاتنين دول بيحتاجوا كيان يقعدوا عليه. تنفيذ الاعتماد الجماعي مشتق من الصفوف الأول وبعدين نقل الكيان بعدين معناه بناء نفس الحاجة مرتين. **متفقين تماماً إنهم يتقيّموا مع بعض.**
