# جولة التحقق على staging — مافيش حاجة ممنوعة، بس **٤ حاجات هتبان عطل وهي مش عطل**

**التاريخ:** 30/09/2026
**لمين:** فريق Next.js — لوحة الشريك (جولة تحقق FE-P2)
**رداً على:** تنبيه الكتابة على staging بحساب الشريك الاختباري

---

## ١. الخلاصة

1. **مافيش ولا وحدة ولا تصريح على staging ممنوع تلمسوه.** اكتبوا براحتكم.
2. **طلب التجديد المعلّق سيبوه زي ما هو** — مش محتاجين نراجعه ولا ننضّفه.
3. **staging شغّال على كود الفرع بالظبط** — مافيش أي تغيير في الكود من آخر نشر (تغييرات اختبارات ووثائق بس).
4. **فيه ٤ حاجات هتبان عطل وهي مش عطل** (§٣) — **اقروها قبل ما تبدأوا.**

---

## ٣. ⚠️ الـ٤ حاجات اللي هتبان عطل

### ٣.١ ماتستخدموش `50047139` في اختبار الرقم المكرر

**`50047139` هو الرقم الوحيد المستثنى من فحص التفرّد** — على staging وعلى الإنتاج. لو استخدمتوه
كـ«رقم مكرر»، **هينجح** بدل ما يرجّع خطأ.

**للاختبار المكرر الحقيقي، استخدموا `TL-TEST-0002-B`** (رقم وحدة `25`):

```json
422 {
  "error": {
    "code": "DUPLICATE_PERMIT_NUMBER",
    "message": "رقم التصريح مستخدم بالفعل في وحدة أخرى",
    "meta": { "permit_number": "TL-TEST-0002-B", "claimed_by_unit_id": 25 }
  }
}
```

### ٣.٢ ماتغيّروش رقم تصريح الوحدة `25`

**`TL-TEST-0002-B` رقم اختاره المالك بالذات عشان يفضل برّه الاستثناءات.** تغييره بيلغي القرار ده.
استخدموه للاختبار (§٣.١) — بس ماتعدّلوهوش.

### ٣.٣ `SUI-386573` هيفشل بـ`claimed_by_unit_id: null` — **عن قصد**

ده العيب المعروف: **وحدة اتمسحت ورقم تصريحها فضل محجوز.** المالك طلب نسيبه على staging **كحالة
الاختبار الحقيقية للإصلاح** اللي هيتعمل قبل الإطلاق.

```json
422 { "error": { "code": "DUPLICATE_PERMIT_NUMBER",
                 "meta": { "permit_number": "SUI-386573", "claimed_by_unit_id": null } } }
```

**`claimed_by_unit_id: null` = العيب ده، مش غلط عندكم.** ماتسجّلوهوش كمشكلة في الجولة.

### ٣.٤ لو عملتوا ← مسحتوا ← عملتوا تاني بنفس رقم التصريح، هتقعوا في نفس العيب

**الرقم بيفضل محجوز بعد المسح.** فلو جولتكم بتعمل وحدة، تمسحها، وتعيد نفس الخطوات:

> **استخدموا رقم تصريح جديد في كل مرة** — مثلاً `FE-P2-{timestamp}-{n}`.

غير كده هيطلعلكم `DUPLICATE_PERMIT_NUMBER` بـ`claimed_by_unit_id: null` من التشغيل التاني.

## ٤. سلوك صحيح — مش عطل

| اللي هتشوفوه | ليه |
|---|---|
| تجديد على وحدة ← أي تجديد تاني **على نفس الوحدة** بيرجّع `RENEWAL_ALREADY_PENDING` | تجديد واحد بس يستنى في المرة. **الوحدات التانية مش متأثرة** |
| الوحدة الـ`pending` ← `PATCH` بيرجّع `409 UNIT_LOCKED` | التعديل مقفول وقت المراجعة. **التجديد مش مقفول** — ده اللي اتفقنا عليه |
| كارت تاريخه منتهي ← `fields.permitExpiresAt` **من غير رقم كارت** | الرد الموثّق — حددوا الكارت بتوقيت الرياض |
| الشقق الجديدة بتاخد بيانات **الباب المفتوح** | الموثّق في الرد اللي فات |
| `permitExpiresAtHijri` بيرجع `null` | طبيعي لو مابعتّوهوش. **شغّال على staging لو حابين تجرّبوه** — اختياري |
