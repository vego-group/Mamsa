## 1. `commissionRate` على صف الإلغاء — اتضاف ✅

اخترنا الحقل مش الاشتقاق، زي ما فضّلتوا. والسبب مش تفضيل أسلوب — الاشتقاق **مش بيرجّع الرقم المجمّد**:

`commission` متخزّن مقرّب لخانتين قبل القسمة، فـ `commission / netBase` بيدي رقم قريب مش مطابق:

| الحالة | `netBase` | `commission` | `commission / netBase` | المجمّد |
|---|---|---|---|---|
| ١٠٪ على ١١٥٠ | 869.57 | 86.96 | **0.1000034500** | 0.1000 |
| ٢٪ على ١١٥٠ | 869.57 | 17.39 | **0.0199983900** | 0.0200 |
| ١٠٪ على ٣٣٣ | 289.57 | 28.96 | **0.1000103602** | 0.1000 |

الانحراف بيكبر كل ما الحجز يصغر. يعني أي مقارنة `=== 0.10` هتفشل، وأي عرض هيحتاج قرار تقريب من عندكم على رقم إحنا مخزّنينه أصلاً.

**الحقل دلوقتي على السطحين:**

```jsonc
// GET /admin/cancellations  →  items[]        (camelCase)
{
  "netBase": 1000.00,
  "commission": 20.00,
  "partnerShare": 980.00,
  "commissionRate": 0.02,      // ← جديد: النسبة اللي الصف اتجمّد عليها
  "impact": -20.00,
  "mamsaOwned": false
}
```

```jsonc
// GET /api/v1/admin/cancellations  →  data[]  (snake_case)
{ "net_base": 1000.00, "commission": 20.00,
  "partner_share": 980.00, "commission_rate": 0.02, "impact": -20.00 }
```

نفس تعريف `commissionRate` الموجود على `/admin/bookings/{id}` بالحرف — `float`، النسبة كـ كسر (٠.٠٢ مش ٢).

## 2. وحدات ممسى المملوكة — الموك بتاعكم **مطابق** ✅

اللي بيتجمّد فعلاً هو **`1.0`**. مش صفر ومش `null`. ده السطر في `Pricing::breakdown()`:

```php
$commissionRate = $mamsaOwned ? 1.0 : (float) config('booking.commission_rate');
$commission     = $mamsaOwned ? $netBase : round($netBase * $commissionRate, 2);
$partnerShare   = round($netBase - $commission, 2);
```

و`BookingController` بيمرّر `(bool) $unit->mamsa_owned` وقت الإنشاء، فالمسار الحقيقي بيوصلها.

السبب اللي خلانا نختار ١.٠: **صفر بيتقري "مافيش عمولة"** على صف المنصة فيه بتاخد القاعدة كلها، و`null` بيكسر `commission === rate × netBase` اللي أنتم معتمدين عليها. وبـ ١.٠ المعادلة صحيحة في كل صف من غير استثناء.

كانت مغطاة بالمبالغ بس مش بالنسبة نفسها — دلوقتي فيه assertion صريحة على `1.0`.

## 3. ملاحظتكم على التغيير المرئي — **تصحيح، مش انحدار** ✅

مؤكد. على وحدة مملوكة لممسى، خسارة ممسى هي القاعدة قبل الضريبة كلها: `commission = netBase = 1,000`، و`impact = -1,000`.

الـ ١,١٥٠ القديمة كانت بتحسب الضريبة خسارة على ممسى، وهي بتتحصّل لصالح الهيئة وبتتوردلها. الرقم الجديد هو الصح.

## 4. حاجة لقيناها في الطريق ⚠️

`/api/v1/admin/cancellations` كان **بيرمي 500 تحت sqlite**، فمكانش عليه ولا تست واحد. سببين، الاتنين MySQL-only:

1. `DATE_FORMAT(...)` في تقرير الشهور — الكود بتاعنا فيه `MapsSpec::ymSql()` بيعالج ده بالظبط ومكانش مستخدم هنا
2. `HAVING` من غير `GROUP BY` في قائمة الشركاء الأكثر إلغاءً — امتداد MySQL، وsqlite بترفضه

على production (MySQL) الاتنين شغالين، فمافيش باج ظهر لحد. المشكلة إن السطح ده مكانش **قابل للاختبار** أصلاً.

اتصلحوا الاتنين. والـ `HAVING` اتحوّل لـ `whereHas` — واتأكدنا إنه مش بيغيّر النتيجة على MySQL الحقيقي مش على الورق:

```
staging (mysql)   HAVING   -> 4:4, 9:4, 5:2
                  whereHas -> 4:4, 9:4, 5:2      identical ids: YES
```

**فيه ٥ مواقع تانية بنفس النمط** (`Api/V1/Admin/ReportController` ×2، `Api/V1/Admin/DashboardController`، `Dashboard/OverviewController` ×2). شغالة على production، وغير قابلة للاختبار بنفس الطريقة. مالمسناهاش دلوقتي عشان مش جزء من طلبكم — قولوا لو عايزينها في جولة جاية.
