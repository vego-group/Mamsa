# القسم أ — سؤال ما قبل الإنتاج

## أ.١ 🔴 الحارس بيتفرّع على **حجم المجموعة**، مش على قيمة التصريح · ✅ **انشروا**

قراءتكم من الوثيقة كانت صح، ودلوقتي مأكدة من الكود مش من النص:

```php
public static function guardGroupSize(Unit $unit, int $size): void
{
    if ($size <= 1) {
        return;              // ← بيخرج هنا قبل ما يقرا license_type أصلاً
    }
    ...
```

الوحدة المستقلة حجم مجموعتها ١، فالميثود **بترجع قبل ما تبص على التصريح نهائياً**. `NULL` على وحدة مستقلة مش بيتفحص، ومستحيل يمنع اعتماد.

### والاختبار اللي طلبتوه — اتكتب بالظبط زي ما وصفتوه

كان عندنا اختبار بيعتمد وحدة مستقلة من غير تصريح، **بس هو بيحط الحالة `pending` مباشرة** — يعني مكانش بيعدّي على مسار التعديل، واللي هو بالظبط الجزء اللي إنتوا قلقانين منه.

ضفنا الرحلة كاملة:

```
test_an_unlicensed_standalone_unit_survives_the_full_edit_and_approve_cycle
```

بيعمل:

1. وحدة مستقلة `approved` وتصريحها `NULL` — **شكل كل وحدة على الإنتاج**
2. الشريك بيعدّل السعر عبر `PUT /api/v1/partner/units/{id}` → **200**
3. FR-066 بيرجّعها `pending` → **متأكد**
4. الأدمن بيعتمدها عبر `POST /admin/approvals/{id}/approve` → **200، والحالة رجعت `approved`**

**لو الحارس اتنقل يوم من الأيام ليتفرّع على القيمة، الاختبار ده بيفشل.**

وضفنا التاني معاه: مبنى مرخّص جوّه حدوده بيتعتمد عادي — عشان الحارس ما يتحوّلش لـ«مفيش حاجة بتتعتمد».

> **الخلاصة: الأثر على الإنتاج صفر فعلاً، والنشر آمن.**

## أ.٢ 🟡 الحاجز على الإنشاء · ✅ **اتنفّذ**

اقتراحكم صح، والحجة اللي معاه هي اللي حسمته: الفحص اليومي بيمسكها **بعد ٢٤ ساعة**، يعني ممكن يعدّي يوم كامل بمجموعة متفرّقة.

`Unit::creating` بقى عليه حاجز، **بشرط مختلف عن حاجز التعديل**:

```php
static::creating(function (self $unit) {
    if (UnitLicense::isWriting() || ! $unit->unit_group_id) return;

    $sibling = self::where('unit_group_id', $unit->unit_group_id)->first([...]);
    if ($sibling === null) return;        // أول صف في مجموعة جديدة — هو اللي بيحدد القيمة

    if (/* القيم مختلفة */) throw new \LogicException(...);
});
```

- صف جديد **من غير مجموعة** → مسموح (مجموعة من واحد)
- **أول** صف في مجموعة جديدة → مسموح، وهو اللي بيحدد القيمة
- صف جديد بينضم لمجموعة قايمة بقيم **مختلفة** → **استثناء**

واختبارين معاه: الحالة اللي وصفتوها (`Unit::create` بمجموعة قايمة وقيمة مختلفة) بترمي، **و**الـ cloner لسه بيقدر يوسّع مجموعة مرخّصة عادي — الحاجز ما يمنعش الطريق الشرعي الوحيد اللي بيكتب في مجموعة قايمة.

**بقيت «مستحيلة» بدل «بتتصاد بعد يوم»** زي ما قلتوا بالظبط.

# القسم ب — نقاط الواجهة الأربعة

## ب.١ 🔴 CORS · ✅ **شغّال** — 🔴 **بس اختبار التأكيد بتاعكم غلط**

### الإجابة: أيوه، بيطلّع CORS، ومن زمان

`config/cors.php` عامل `'paths' => ['*']` — يعني **كل** مسار، بما فيهم المرفقات. والأصول اللي في الـ allowlist على staging دلوقتي تشمل اللي طلبتوه:

```
localhost:3000 · localhost:3001 · localhost:3002
mamsa-partner-dashboard.vercel.app
test.mamsaa.com · test-partner.mamsaa.com · test-admin.mamsaa.com
+ نمط:  ~^https://mamsa-[a-z0-9-]+\.vercel\.app$~
CORS_SUPPORTS_CREDENTIALS=true
```

اتأكدنا حي، مش من الإعداد:

```
Origin: http://localhost:3002            → access-control-allow-origin: http://localhost:3002 ✅
Origin: http://localhost:3001            → access-control-allow-origin: http://localhost:3001 ✅
Origin: …mamsa-partner-dashboard.vercel.app → موجود ✅
Origin: https://evil.example.com         → مفيش هيدر ✅ (الـ allowlist شغّالة)
```

### 🔴 بس اختبار التأكيد اللي كتبتوه هيديكم نتيجة غلط

كتبتوا: «اطلب مرفق بـ `id` مش موجود من اللوحة. لو ظهرت *المرفق غير متاح* يبقى الـ CORS شغّال.»

**الاختبار ده هيدي `403` دايماً — حتى والـ CORS شغّال ١٠٠٪.**

السبب: المسار عليه middleware **`signed`**. الطلب من غير توقيع صالح بيترفض **قبل ما يوصل للكونترولر خالص**، فما بيوصلش لمنطق الـ 404 أبداً:

```
/complaints/attachments/999999                    (من غير توقيع)  → 403
/complaints/attachments/999999?expires=…&signature=…  (توقيع صالح) → 404   ✅
```

الاتنين اتجربوا حي على staging، والاتنين طلّعوا `access-control-allow-origin`.

### 👉 التفرقة شغالة — **بس على الرابط الموقّع نفسه**

```
رابط موقّع صالح + المرفق موجود   → 200
رابط موقّع صالح + المرفق اتمسح   → 404   ← «المرفق غير متاح»
توقيع منتهي أو معدّل أو غايب      → 403   ← «الرابط انتهى، حدّث الصفحة»
```

**فالـ probe لازم يستخدم نفس الـ URL الموقّع اللي الـ `<img>` فشل عليه** — مش URL مبني بالـ id. وده كويس عملياً: هو نفس الرابط اللي معاكم أصلاً.

> لو جربتوا بالطريقة اللي كاتبينها، هتستنتجوا إن الـ CORS مكسور وهو سليم، وتدوّروا في المكان الغلط.

## ب.٢ 🔴 `cancelled_by` — المجموعة الكاملة · **وفيه باج لقيناه**

جردنا كل كاتب للعمود في الكود. **أربع قيم، ومفيش غيرهم:**

| القيمة | مين | بيتكتب فين |
|---|---|---|
| `customer` | الضيف لغى بنفسه | `CancelBookingAction` — لما المنفّذ هو صاحب الحجز |
| `admin` | الإدارة لغت نيابةً عنه | `CancelBookingAction` — منفّذ مش صاحب الحجز |
| `partner` | المضيف لغى | `HostCancelBookingAction` |
| `system` | تلقائي (انتهاء مهلة الدفع) أو من غير منفّذ | `ExpirePendingBookings` + `CancelBookingAction` بمنفّذ `null` |

**مقفولة؟** `varchar(20)` مش enum على مستوى القاعدة، فمفيش قيد محرك. بس دي كل المسارات الموجودة، **وأي قيمة جديدة هتتبلّغ لكم قبل ما تتنشر**.

الأرقام الحقيقية على staging: `system: 12` · `partner: 5` · `customer: 1` · **مفيش `null` ولا قيم تانية**. الإنتاج: **صفر حجوزات ملغية** خالص.

### 🔴 والباج: `cancelled_by_label` كان بيرجّع `null` لإلغاء المضيف

```php
match ($this->cancelled_by) {
    'customer' => 'العميل',
    'admin'    => 'الإدارة',
    'system'   => 'النظام',
    default    => null,      // ← 'partner' كان بيقع هنا
};
```

يعني إلغاء المضيف — **وهو أكتر نوع الضيف محتاج يفهمه** — كان بيرجّع `cancelled_by: "partner"` ومعاه `cancelled_by_label: null`، وأي شاشة بتعرض الـ label ما كانتش بتعرض حاجة.

**اتصلح:** `'partner' => 'المضيف'`. الأربعة كلهم مغطيين دلوقتي.

> **وقراركم بتغيير الـ fallback لصياغة محايدة صح ونصيحتنا بيه** — بس مش عشان القيم ناقصة، عشان `default → الضيف` **بيتهم الضيف بحاجة ما عملهاش**. خلّوه محايد حتى والقايمة كاملة.

## ب.٣ 🟠 `cancellation` بيظهر في **كل** الإلغاءات

```php
'cancellation' => $this->when($this->status === 'cancelled', fn () => [...]),
```

الشرط هو **الحالة بس** — مش نوع الملغي. فأي حجز `cancelled`، مهما كان مين لغاه، بيرجّع الـ block كامل بنفس الشكل. الكارت ممكن يتبني على وجوده بأمان.

## ب.٤ 🟡 `refunded_amount` — **رقم**، ومعاه فخ أهم من النوع

`Payment::$casts` فيه `'refunded_amount' => 'float'` → JSON **number**، مش string. `1000.00` بتوصلكم `1000`.

### ⚠️ الفخ الحقيقي: المفتاح ممكن **يختفي**، مش يبقى `null`

```php
'refunded_amount' => $this->whenLoaded('payment', fn () => $this->payment?->refunded_amount),
```

`whenLoaded` معناها إن المفتاح **مش موجود في الرد** لو علاقة `payment` مش متحمّلة — نفس فخ `available_count` بالظبط. وأي كود بيعمل `?? 0` وهو مستني `null` هيشتغل هنا صح، بس اللي بيعمل `"refunded_amount" in obj` هيتفاجئ.

**على سطح الضيف الاتنين متحمّلين دايماً** — اتأكدنا:

| المسار | `payment` متحمّلة؟ |
|---|---|
| `GET /api/v1/bookings/{id}` | ✅ `load([… 'payment' …])` |
| `GET /api/v1/user/bookings` | ✅ `with([… 'payment' …])` |

**فالمفتاح حاضر دايماً على سطح الضيف.** ممكن يبقى `null` بس لو الحجز مالوش صف دفع أصلاً (حجز اتلغى قبل أي محاولة دفع).

**القاعدة:** `null` و«غايب» و`0` كلهم معناهم **متعرضش أي كلام عن استرداد**. سلوككم الحالي (أي قيمة مش مقروءة أو سالبة → `0` → سكوت) **صح، وما بيخفيش مبلغ حقيقي** لأن النوع رقم والمفتاح حاضر.
