# الخطوة ٢ — الوثائق بقت خلف رابط موقّع · **مبنية، لسه ما اتنشرتش**

**التاريخ:** 11/09/2026
**للمستودعات:** `mamsa-admin-dashboard` · `mamsa-partner-dashboard`
**الحالة:** ✅ **الكود جاهز ومختبر** · ⏸️ **مش منشور على أي بيئة** — النشر هو النافذة اللي بنتحرّك فيها مع بعض

الخطوة ٢ اتبنت: **الكتابة بقت على القرص الخاص، والقراءة بقت رابط موقّع.** النصّين في deploy واحد لأنهم مايتفصلوش — تحويل الكتابة لوحده بيخلي الشاشة تأشّر على مسار عام الملف مش عليه، وتحويل القراءة لوحده بيوقّع روابط لملفات لسه مكشوفة.

**مفيش حاجة اتغيرت عندكم لحد دلوقتي.** المستند ده عشان تعرفوا بالظبط إيه اللي هيتغيّر في النافذة.

---

## ١. 🔴 الحقول اللي هتتغيّر — **القيمة بس، مش الاسم**

كل مفتاح تحت **موجود بنفس الاسم**، وقيمته هتتحوّل من رابط دائم على `/storage/…` لرابط موقّع على `/documents/…`.

### لوحة الأدمن

| الرد | المفتاح |
|---|---|
| `GET /admin/approvals/{id}` | `unit.permitFileUrl` · `unit.ownershipDocUrl` |
| `GET /admin/units/{id}` | نفس المفتاحين |
| شاشة الشركاء | `fileUrl` (مستندات الشريك) |
| `GET /api/v1/admin/requests/{id}` | `fileUrl` (شهادة البنك · وثيقة الملكية) |

### لوحة الشريك

| الرد | المفتاح |
|---|---|
| `GET /me` / الملف الشخصي | `crUrl` (السجل التجاري) |
| `GET /api/v1/partner/units/{id}` | `tourism_permit_url` · `ownership_doc_url` · `bank_certificate_url` |

**قبل:**
```
https://api.mamsaa.com/storage/dashboard/license_pdf/file_01kx….pdf
```
**بعد:**
```
https://api.mamsaa.com/documents/file_01kx…?expires=1789162494&signature=6fe37e…
```

> **الأسماء ما اتغيرتش، والقيم لسه strings أو `null`.** لو بتعرضوا الرابط في `<iframe>` أو `<a>` من غير ما تفكّوه، التغيير شكلياً صفر — **بشرط القسم ٢.**

---

## ٢. 🔴 الشرط الوحيد اللي لازم يتعمل قبل النافذة

الرابط الجديد **بيتطلب كوكي جلسة**. التوقيع لوحده بيرجّع **403**.

و`SESSION_SAME_SITE` مختلف بين البيئتين:

```
staging : none  → الكوكي بيتبعت من أي أصل، في أي إطار
الإنتاج : lax   → same-site بس
```

| أصل اللوحة | تأطير رابط الـ API مباشرةً على الإنتاج |
|---|---|
| `admin.mamsaa.com` · `partner.mamsaa.com` | ✅ شغّال |
| `*.vercel.app` (معاينة) | 🔴 **403 — الكوكي ما بيتبعتش** |

### 👉 المطلوب: **عدّوا الوثيقة على الـ proxy بتاعكم**

```
<iframe src="/api/proxy/documents/{uploadId}?expires=…&signature=…" />
```

السيرفر بتاعكم بيجيب الملف بالكوكي (server-to-server، مفيش `SameSite` أصلاً) ويرجّعه من **أصلكم** — فالإطار same-origin وبيشتغل على كل بيئة ومعاينة.

**مرّروا `Content-Type` و`Content-Disposition` زي ما جم.**

> ✅ **ده تقدروا تعملوه دلوقتي** — بيشتغل مع الروابط القديمة برضو، فمش محتاج يستنى النافذة. **وده أهم بند تجهيزي.**

---

## ٣. اللي **ما اتغيرش**

- **صور الوحدات** — عامة زي ما هي، على `/storage/…`. متعدّوهاش على المسار الجديد: ده هيحط كل صورة إعلان في PHP.
- **مرفقات الشكاوى** — مسارها وتوقيعها زي ما هما (١٥ دقيقة، من غير فحص جلسة).
- **أسماء كل المفاتيح** فوق.
- **`…FileId`** (`crFileId` · `nationalIdFileId` · `tourismLicenseFileId`) — ثابتة، ودي اللي بتتبعت في أجسام الكتابة.

## ٤. تغييران في ردود الرفع

### أ. رفع وثيقة مش هيرجّع `url`

```jsonc
// رفع صورة وحدة  (unit_photo)
{ "fileId": "file_01…", "url": "https://…/storage/dashboard/unit_photo/file_01….jpg" }

// رفع وثيقة  (license_pdf · company_doc · ownership_doc)
{ "fileId": "file_01…" }          ← مفيش url
```

**المفتاح بيختفي، مش بيبقى `null`.** الوثيقة مالهاش رابط عام بعد دلوقتي، وإرجاع رابط بيدي 404 أسوأ من إننا ما نرجّعش حاجة. **`fileId` هو اللي بيتبعت في جسم الكتابة زي ما هو.**

لو محتاجين تعرضوا الوثيقة فوراً بعد الرفع، اطلبوا الشاشة تاني وخدوا الرابط الموقّع من الرد.

### ب. `POST /api/v1/partner/units/{unit}/documents`

```jsonc
{ "data": {
    "type": "tourism_permit",
    "path": "file_01m…",                    ← بقى معرّف رفع، كان مسار خام
    "url":  "https://…/documents/file_01m…?expires=…&signature=…"
} }
```

المسار ده كان بيخزّن مسار خام (`units/12/docs/abc.pdf`)، والمسار الخام **مايتوقّعش** — المسار الموقّع بيحلّ صف الرفع عشان يعرف مين من حقه يقرا، والمسار الخام مالوش مالك يتفحص. بقى يسجّل صف، فكل الوثائق في النظام بقت متسقة.

> **لو في كودكم أي حاجة بتفترض إن القيمة دي مسار فيه `/`، صلّحوها.** بقت معرّف `file_…` زي باقي الأسطح.

## ٥. حالات الفشل

| الحالة | الكود | التصرف |
|---|---|---|
| رابط منتهي (> ساعتين) | **403** | «الرابط انتهى — حدّث الصفحة» |
| رابط من غير توقيع أو معدّل | **403** | نفس المعاملة |
| الجلسة مش موجودة / مش من حق الطالب | **403** | 👆 غالباً الكوكي مش بيتبعت — القسم ٢ |
| الوثيقة مش موجودة | **404** | «المستند غير متاح» |

**التلاتة الأوائل 403 بقصد** — التفرقة بينهم بتأكّد لطرف غير مصرّح إن المعرّف ده موجود.

## ٦. الترتيب

```
١ (تم)      المسار الموقّع منشور على staging · بيقرا من القرصين · مفيش حاجة اتبدلت
٢ (جاهز)    الكتابة للقرص الخاص + القراءة للرابط الموقّع  ← deploy واحد · النافذة دي
٣ (بعدها)   الملفات القديمة تترحّل
```

**المسار بيقرا من القرصين** من أول يوم بقصد، فالوثائق القديمة بتفضل شغالة بعد الخطوة ٢ وقبل الترحيل. **مفيش فجوة بين ٢ و٣.**

### الترتيب المقترح للنافذة

1. ننشر الخطوة ٢ على **staging**
2. إنتوا تحوّلوا اللوحتين على staging وتأكدوا (مفيش سقف زمني — خدوا وقتكم)
3. لما تقولوا جاهزين، ننشر على **الإنتاج** بلقطة قبل/بعد وأول رفع حقيقي يتأكد كامل

## ٧. قايمة التجهيز

- [ ] **مسار الـ proxy للوثائق** (القسم ٢) — **دلوقتي، مش في النافذة**
- [ ] `403` = «حدّث الصفحة»، مش خطأ خادم
- [ ] متخزّنوش الرابط في state طويل العمر ولا `localStorage` — عمره ساعتان وهو بيانات اعتماد
- [ ] رفع وثيقة: متعتمدوش على `url` في الرد — استخدموا `fileId`
- [ ] `data.path` من مسار وثائق الوحدة بقى معرّف مش مسار
- [ ] نقطة واحدة لكل رابط وثيقة (`PermitFile.tsx` عند الأدمن) — التبديل يبقى سطر
