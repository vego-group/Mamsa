# دليل تنفيذ الواجهات — الوحدات المتعددة والتصريح

**التاريخ:** 11/09/2026
**للمستودعات:** `mamsa-partner-dashboard` · `mamsa-admin-dashboard` · `mamsa-app`
**حالة الباك اند:** ✅ **كامل ومنشور على staging** · ✅ **التصريح منشور على الإنتاج**

المستند ده **كل اللي محتاجينه للتنفيذ**، بعقود متأكدة من الخادم مش مكتوبة من الذاكرة.

---

## ٠. قبل ما تبدأوا — إصلاح مهم اتعمل النهاردة

كان فيه **فجوة كانت هتوقف الميزة كلها**: التصريح كان **يتقرا** من سطح اللوحة و**يتكتب** من سطح `/api/v1` بس.

والتوسيع مرفوض إلا لو التصريح `tourist_facility` — **فمكانش فيه أي طريقة الشريك يوصل للقيمة دي من اللوحة**، وكل توسيع كان هيترفض بسبب تصنيف مفيش شاشة تقدر تحطه.

**اتصلح:** `PATCH /units/{id}` بقى يقبل `licenseType` و`licensedUnitsCount`. **التصنيف والتوسيع بقوا متوصلين.**

> لو كنتوا بدأتوا شاشة توسيع قبل كده وشوفتوا `MULTI_UNIT_REQUIRES_FACILITY_LICENSE` على طول — **ده كان السبب، مش خطأ عندكم.**

# القسم أ — لوحة الشريك

## أ.١ تصنيف الوحدة (شاشة التعديل)

```http
PATCH /units/{id}
Content-Type: application/json
```

```json
{ "licenseType": "tourist_facility", "licensedUnitsCount": 8 }
```

| الحقل | القيم | ملاحظات |
|---|---|---|
| `licenseType` | `"tourist_facility"` · `"private_hospitality"` · `null` | `null` = غير مصنّف (كل الوحدات القائمة) |
| `licensedUnitsCount` | عدد ١–١٠٠ · `null` | **إلزامي** مع `tourist_facility` |

**القراءة من نفس المسار** (`GET /units/{id}`) — **camelCase**:

```json
{ "licenseType": "tourist_facility", "licensedUnitsCount": 8, "groupSize": 5 }
```

> `groupSize` **عدد صحيح دايماً**، و**`1`** للوحدة المستقلة. **عمره ما يبقى `null` ولا غايب** — اعرضوه من غير تفرّع.

### أكواد الرفض على `PATCH`

| الكود | HTTP | متى | الرسالة المقترحة |
|---|---|---|---|
| `LICENSED_UNITS_COUNT_REQUIRED` | 422 | سياحي من غير عدد | «أدخل عدد الوحدات المذكور في التصريح» |
| `LICENSED_UNITS_COUNT_NOT_APPLICABLE` | 422 | خاص بعدد > ١ | «تصريح الضيافة الخاصة يغطي وحدة واحدة» |
| `QUANTITY_EXCEEDS_LICENSED_UNITS` | 422 | العدد الجديد < حجم المبنى الحالي | استخدموا `meta.group_size` |
| `LICENSE_DOWNGRADE_BLOCKED_BY_QUANTITY` | 422 | تحويل مبنى قايم لتصريح خاص | 👇 |
| `VALIDATION` | **400** | قيمة مش من القايمة | `error.fields` |

> ⚠️ **`LICENSE_DOWNGRADE_BLOCKED_BY_QUANTITY`:** الرد فيه **`meta.shrink_supported: false`**.
> **اتفرّعوا على الحقل ده مش على النص.** مفيش مسار تقليص لسه؛ لما يتعمل الحقل يبقى `true` **من غير ما تغيّروا أي كوبي**.

## أ.٢ توسيع المبنى — الشاشة الرئيسية

```http
POST /units/{id}/apartments
```

```json
{ "count": 8 }
```

### 🔑 `count` **إجمالي مش إضافة**

| الحالة | الطلب | النتيجة |
|---|---|---|
| مبنى فيه ٥ | `{"count": 8}` | بيبقى ٨ · **`added: 3`** |
| مبنى فيه ٨ | `{"count": 8}` | بيفضل ٨ · **`added: 0`** |
| مبنى فيه ٨ | `{"count": 3}` | بيفضل ٨ · **`added: 0`** · ❗ **مش بيحذف** |

**الشاشة لازم تقول «عندي كام وحدة إجمالاً» مش «ضيف كام»** — والفرق بين الاتنين هو الفرق بين مبنى ٨ ومبنى ١٣.

### الرد `200`

```json
{
  "groupId":   "01M19EZRB4ARP4BDGJ4ET7P03F",
  "groupSize": 8,
  "added":     3,
  "units": [
    { "id": "u_30", "apartmentNo": "401", "status": "approved" },
    { "id": "u_43", "apartmentNo": "406", "status": "pending" },
    { "id": "u_44", "apartmentNo": "407", "status": "pending" }
  ],
  "message": "تمت إضافة 3 وحدة وهي قيد المراجعة. مبناك الحالي يستمر في استقبال الحجوزات."
}
```

**الشقق الجديدة بترجع `pending` — الخادم بيقدّمها بنفسه.** متعملوش `submit` ورا التوسيع.

**رسالة النجاح:** اعرضوا `added` للتأكيد و`groupSize` للحالة. لو `added === 0` اعرضوا «المبنى يحتوي بالفعل على هذا العدد» — **مش** «تمت الإضافة».

### أكواد الرفض على التوسيع

| الكود | HTTP | `meta` | المعنى |
|---|---|---|---|
| `MULTI_UNIT_REQUIRES_FACILITY_LICENSE` | 422 | `license_type`, `max_units` | صنّف الوحدة الأول |
| `QUANTITY_EXCEEDS_LICENSED_UNITS` | 422 | `requested`, **`licensed_units_count`** | «تصريحك يغطي {n} وحدة» |
| `MULTI_UNIT_DISABLED` | 422 | — | الميزة مقفولة |
| `VALIDATION` | **400** | `error.fields` | `count` ناقص أو غير صالح |
| — | **404** | — | الوحدة مش بتاعت الشريك |

### 🔴 شكل المغلّف — **الفرق ده بيكسر الكود**

```jsonc
// 422 و 409 — الرفض بمنطق العمل
{ "error": { "code": "QUANTITY_EXCEEDS_LICENSED_UNITS",
             "message": "…",
             "meta": { "requested": 9, "licensed_units_count": 8 } } }

// 400 — خطأ إدخال
{ "error": { "code": "VALIDATION", "message": "بيانات غير صالحة",
             "fields": { "count": "عدد الوحدات مطلوب" } } }
```

- **الرقم في `error.meta.licensed_units_count`** — مش في جذر `error`.
- **`meta` بتختفي خالص لو مفيش أرقام** — متعملوش `error.meta.x` من غير فحص.
- **`meta` ≠ `fields`**: `fields` بيقول أنهي إدخال غلط، `meta` بيقول شكل الدنيا.

### ⚠️ حالة لازم تتعالج

**`PATCH` على وحدة حالتها `pending` بيترفض بـ `409 UNIT_LOCKED`.** يعني شريك وسّع مبناه ولسه تحت المراجعة **مش هيقدر يعدّل** لحد ما المراجعة تخلص. **اقفلوا زراير التعديل لما `status === "pending"`.**

## أ.٣ الترتيب اللي الشاشة بتمشي بيه

```
١. الوحدة غير مصنّفة (licenseType === null)
   └─> اعرض «صنّف وحدتك» — PATCH بـ licenseType (+ licensedUnitsCount لو سياحي)

٢. مصنّفة private_hospitality
   └─> اخفِ التوسيع تماماً. التصريح ده بيغطي وحدة واحدة بتعريفه

٣. مصنّفة tourist_facility
   └─> اعرض «مبناك فيه {groupSize} من {licensedUnitsCount}»
   └─> التوسيع: رقم إجمالي، الحد الأعلى licensedUnitsCount
   └─> بعد النجاح: اعرض added + «قيد المراجعة»
```

# القسم ب — لوحة الأدمن

## ب.١ شاشة المراجعة

```http
GET /admin/approvals/{id}
```

```json
{
  "unit": {
    "tourismPermitNo":    "TL-123456",
    "permitFileUrl":      "https://api.mamsaa.com/storage/dashboard/license_pdf/file_….pdf",
    "licenseType":        "tourist_facility",
    "licensedUnitsCount": 8,
    "groupSize":          5
  }
}
```

**المسار: `unit.licenseType` · `unit.licensedUnitsCount` · `unit.groupSize`.**

### 🎯 شغل المراجع — التلاتة مع بعض بقصد

النظام **بيرفض** أي مجموعة أكبر من العدد المعلن. **فالمراجع مش بيراجع الحجم — بيراجع صدق الرقم المُدخل.**

يعني الشاشة لازم تعرض في نفس المكان:

```
العدد المُدخل: 8   ←  الشريك كتبه
حجم المبنى:   5   ←  الواقع
ملف التصريح:  [إطار]  ←  الرقم الحقيقي مكتوب هنا
```

**من غير التلاتة مع بعض المراجعة بتتحول لضغطة زرار.**

### ⛔ ملف التصريح — موقوف عن الإنتاج

التأطير شغّال (مفيش `X-Frame-Options`)، **بس ملفات التصاريح والهويات على الإنتاج مكشوفة بلا مصادقة ولا انتهاء صلاحية**. البند مرفوع أمنياً.

**كارت التصريح يفضل مقفول على الإنتاج لحد ما الملفات تتأمّن** — زي ما اتفقنا. على staging اشتغلوا عادي.

**شكل الرابط هيتغيّر** لما الحل ينزل (`/documents/{id}?expires=…&signature=…`) — **هنبلّغكم قبل النشر بوقت كافي.**

# القسم ج — تطبيق الضيف

## ✅ **مفيش أي شغل مطلوب**

متحقق حي على الخادم:

| السلوك | الحالة |
|---|---|
| مبنى ٥ شقق = **بطاقة واحدة** | ✅ متأكد — ١٦ وحدة رجعت بـ ١٦ `listing_id` مختلف |
| كل الشقق محجوزة = **بيختفي من النتايج** | ✅ مختبر — مش بيظهر بصفر |
| بدون تواريخ = بيظهر تاني | ✅ السؤال بيتغيّر من «فاضي» لـ«موجود» |
| التصريح **مش** في مغلّف الضيف | ✅ ٣٢ مفتاح، ولا واحد فيهم تصريح |

`available_count` و`listing_id` موجودين من قبل ومعناهم ما اتغيرش.

> **قاعدة على `available_count`:** من غير تواريخ بيجاوب **«هل ده معلن؟»** مش «هل ده متاح؟». **متعرضوش «متاح الآن»** قبل ما الضيف يختار تواريخ.
