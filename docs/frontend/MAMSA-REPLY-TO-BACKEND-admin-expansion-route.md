## ١. العقد

```
POST /admin/units/{id}/apartments
Cookie: admin-panel session · صلاحية units.manage
Body:  { "count": 6 }
```

**`count` = إجمالي المجموعة بعد العملية، مش إضافة.** نفس دلالة سطح الشريك بالظبط، عشان لو استخدمتوا نفس المكوّن ما يبقاش فيه مفاجأة: إعادة إرسال نفس الرقم بتضيف صفر، والتصغير **ما بيتنفّذ** (وحدة ممكن تكون عليها حجز) — بيرجع `added: 0` والمجموعة زي ما هي.

### الرد `200`

```json
{
  "groupId": "01M2X9KB223ZK9N7NZDBX5YW5D",
  "groupSize": 4,
  "added": 3,
  "units": [
    { "id": "57", "apartmentNo": "1", "status": "approved" },
    { "id": "61", "apartmentNo": "2", "status": "pending" },
    { "id": "62", "apartmentNo": "3", "status": "pending" },
    { "id": "63", "apartmentNo": "4", "status": "pending" }
  ],
  "message": "تمت إضافة 3 وحدة وهي قيد المراجعة. الوحدة الأصلية تستمر في استقبال الحجوزات."
}
```

`groupSize` هو اللي المبنى بيحتويه **دلوقتي** — مش اللي اتطلب. بيختلفوا لما `count` أقل من أو يساوي الحجم الحالي.

### الرفض — كله بغلاف الأدمن `{ message, code, fields?, meta? }`

| HTTP | `code` | يعني | اللي معاه |
|---|---|---|---|
| `403` | `NOT_MAMSA_OWNED` | وحدة شريك — الشريك يوسّعها من لوحته | — |
| `409` | `SOURCE_NOT_APPROVED` | الأصل draft/pending/rejected — اعتمده أولاً | — |
| `422` | `VALIDATION_ERROR` | `count` غايب / مش رقم / خارج 1..100 | `fields.count` |
| `422` | `MULTI_UNIT_REQUIRES_FACILITY_LICENSE` | الأصل مش مصنّف `tourist_facility` | `meta: { license_type, max_units: 1 }` |
| `422` | `QUANTITY_EXCEEDS_LICENSED_UNITS` | العدد أكبر من التصريح | `meta: { requested, licensed_units_count }` |
| `422` | `SOURCE_UNIT_INCOMPLETE` | الأصل معتمد بس ناقص (زي #39) | `fields` بأسماء حقول الويزارد + `meta: { unitId }` |
| `422` | `APARTMENT_INCOMPLETE` | نسخة ما عدّتش البوابة — العملية كلها اترجعت | `fields` + `meta: { apartmentNo }` |

**`meta` جديد على غلاف الأدمن — إضافي**، بيظهر بس لما فيه أرقام يتكلم عنها. «تصريحك يغطي 6» بتتعرض من `meta.licensed_units_count` مش من قراءة الجملة العربية. الردود الحالية ما اتغيّرت.

## ٢. اللي بيتعمل فعلاً

**النسخ بتتقدّم للمراجعة (`pending`).** بتظهر في `/admin/approvals` باسم «ممسى» و`mamsaOwned: true`، وقيد في feed الأدمن لكل وحدة، و`submitted_at` مختوم من نفس الـ observer بتاع كل مسارات التقديم. الأصل بيفضل معتمد وبيستمر في استقبال الحجوزات.

**قبل أي كتابة:**

1. الأصل لازم يكون **معتمد** — التوسيع لوحدة منشورة، مش لمسودة
2. الأصل لازم يعدّي **نفس بوابة الاكتمال** اللي التقديم بيعدّيها — الاعتماد **مش** ضمانة لده، و#39 على الإنتاج معتمدة وهتقع هنا
3. التصريح لازم يغطي المبنى
4. الوثائق بتنتقل مع النسخ
5. **atomic** — نسخة واحدة تقع، العملية كلها بترجع

## ٣. 🟡 قرار اتخذناه وبنقوله صريح: مش ورا `MULTI_UNIT_ENABLED`

العلم ده على الإنتاج `false` «لحد ما واجهة الشريك تنزل». تعليقه في الكود بيقول إنه **مفتاح طرح للشركاء**، مش بوابة قانونية — البوابة القانونية هي التصريح، وده بيتفرض في كل الحالات.

المنصة وهي بتوسّع مخزونها هي مش «طرح الشركاء». فمسار الأدمن **مش ورا العلم**. لو كان وراه، كان هيبقى ميت على الإنتاج — المكان الوحيد اللي محتاجينه فيه — لحد ما واجهة الشريك تنزل، وده ربط بين طرحين ما بينهمش علاقة.

**وده كشف حاجة تانية اتصلحت:** فحص الاعتماد في `/admin/approvals/{id}/approve` كان فيه العلم جواه. يعني لو أدمن عدّل وحدة واحدة من مبنى حيّ (تعديل → pending)، **ما كانش ممكن يعتمدها تاني** طول ما توسيع الشركاء مقفول — الوحدة بتقعد برّه المتجر لسبب ما ليهاش علاقة بيه. دلوقتي الاعتماد بيفحص **التصريح بس**، والاختبار المقابل بيأكد إن التصريح لسه بيتفرض عند إعادة الاعتماد.

لو الرأي إن مسار الأدمن كمان يقف ورا العلم — سطر واحد، قولوا.

## ٤. المتجر — المبنى كارت واحد

بعد التوسيع، `/api/v1/units` بيرجّع **كارت واحد** للمبنى بـ `available_count` (عدد الوحدات المتاحة في التواريخ المطلوبة، أو الكل بدون تواريخ):

```json
{ "id": 57, "available_count": 4, "owner": { "id": 36, "name": "ممسى", "type": "mamsa" } }
```

ده الشكل اللي #34 و#35 على الإنتاج **المفروض** يبقوا عليه — كارت واحد لاستوديو روش هوم بدل اتنين متطابقين. ⚠️ تطبيق الضيف لازم يبقى بيقرا `available_count` قبل ما نعمل ده على الإنتاج، وإلا الكارت هيقول «استوديو» من غير ما يقول إن فيه أربعة.

## ٥. على staging دلوقتي — للتجربة

سبنا المبنى اللي اتعمل في الاختبار عشان تبنوا عليه:

- **«اختبار مبنى ممسى»** — الأصل `#57` معتمد، النسخ `#61 #62 #63` **في طابور المراجعة**، مجموعة `01M2X9KB223ZK9N7NZDBX5YW5D`، تصريح `tourist_facility / 6`
- تقدروا تجرّبوا `count: 5` أو `6` (بيضيف)، `9` (بيرفض بـ `QUANTITY_EXCEEDS_LICENSED_UNITS` و`meta`)، `3` (`added: 0`)
- الأدمن التجريبي `+966555000003` بالكود الثابت

**ملاحظة على الترتيب في الواجهة:** الوحدة لازم تكون مصنّفة `tourist_facility` بـ `licensedUnitsCount` **قبل** التوسيع — من الويزارد أو `PATCH /admin/units/{id}` (كاتب التصريح شغّال على الأدمن دلوقتي على الاتنين staging والإنتاج). وحدة غير مصنّفة → `MULTI_UNIT_REQUIRES_FACILITY_LICENSE`. فزرار «أضف وحدات» منطقي يظهر مفعّل بس لما `licenseType === "tourist_facility"`.
