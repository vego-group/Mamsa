# التجديد — وحدة قيد المراجعة تصريحها انتهى · و`permitAddress` بيتورّث إزاي

**التاريخ:** 30/09/2026
**لمين:** فريق Next.js — لوحة الشريك (وجزء للوحة الأدمن في §٢)
**الحالة:** ده **سلوك الكود من الأول** — ماتغيّرش حاجة. اللي اتعمل: اتوثّق في العقد، واتثبّت بـ٩ اختبارات.
**على الإنتاج وstaging بنفس الشكل.**

---

## ١. الخلاصة

1. **وحدة `pending` تصريحها انتهى: التجديد شغّال** — وهو الطريق الوحيد، لأن الويزارد مقفول.
   **زرار التجديد لازم يظهر للوحدات الـ`pending` كمان.**
2. **لوحة الأدمن:** التجديد المستني **مش** جوّه `permit` في شاشة المراجعة — هو في
   `unit.pendingRenewalId`. شاشة بتعرض `permit.status` بس هترفض شريك صلّح فعلاً.
3. **`permitAddress` في التجديد بيتورّث حقل حقل.** `null` معناها «زي ما هو»، **مش** «امسح» —
   **عكس** `PATCH /units/{id}`.

---

## ٢. سؤال ١ — وحدة `pending` وتصريحها انتهى

### الإجابة: التجديد شغّال

| المسار | وحدة `pending` |
|---|---|
| `PATCH /units/{id}` (الويزارد) | ❌ **409 `UNIT_LOCKED`** |
| `POST /units/{id}/permit-renewals` | ✅ **201** — والوحدة **بتفضل** `pending` |

**`UNIT_LOCKED` بيطلع من التعديل بس.** التجديد مالوش أي شرط على حالة الوحدة — بيتأكد من التصريح
بس (فيه تصريح حالي، مافيش تجديد تاني مستني، التاريخ في المستقبل).

**وتقديم التجديد مابيطلّعش الوحدة من المراجعة** — مختبَر.

### المطلوب في لوحة الشريك

**زرار التجديد يظهر للوحدة الـ`pending`** — على الأقل لما `permitStatus` يبقى `expired` أو `expiring`.

| حالة الوحدة | لو التصريح انتهى، الشريك يعمل إيه |
|---|---|
| `approved` | **تجديد** |
| **`pending`** | **تجديد** ← ده الناقص عندكم دلوقتي |
| `draft` · `rejected` | يعدّل `permitExpiresAt` من الويزارد مباشرة — التعديل مش مقفول |

### ⚠️ للوحة الأدمن — هنا العطل اللي وصفتوه كان هيحصل فعلاً

```jsonc
GET /admin/approvals/{id}

{
  "permit": {
    "status": "expired",          // ← ده اللي المراجع هيشوفه
    "expiresAt": "…",
    …
  },
  "unit": {
    "pendingRenewalId": "31",     // ← والتجديد المستني هنا، مش جوّه permit
    …
  }
}
```

**الشاشة لازم تعرض `unit.pendingRenewalId` جنب `permit.status`** — مثلاً «منتهي · فيه تجديد
مستني المراجعة». من غيرها المراجع يشوف تصريح ميت ويرفض شريك عمل كل حاجة صح.

### التجديد والوحدة — قرارين منفصلين، وأي ترتيب بيوصل

**اعتماد الوحدة مابيعتمدش التجديد، واعتماد التجديد مابيعتمدش الوحدة.** المراجع لازم ياخد الاتنين:

| الترتيب | اللي بيحصل |
|---|---|
| **التجديد الأول** (`POST /admin/permit-renewals/{id}/approve`) | الوحدة تفضل `pending` ← اعتماد الوحدة ← **بتبيع** |
| **الوحدة الأول** (`POST /admin/approvals/{id}/approve`) | الوحدة `approved` **بس مابتبيعش** ← اعتماد التجديد ← **بتبيع** |

**ليه الوحدة ممكن تبقى `approved` ومابتبيعش:** اعتماد الوحدة مابيفحصش تاريخ التصريح. الانتهاء
**بيتحسب وقت البيع**، مش حالة بتتكتب — فوحدة معتمدة بتصريح منتهي مابتظهرش للضيف (404) لحد ما
التجديد يتعتمد.

## ٣. سؤال ٢ — `permitAddress` في التجديد

### الإجابة: بيتورّث **حقل حقل**

| اللي بتبعتوه | العنوان في التجديد |
|---|---|
| `permitAddress` **غايب خالص** | **بيتورّث كله** من التصريح الحالي |
| **الأربع قيم `null`** | **بيتورّث كله** — `null` معناها «زي ما هو» |
| `""` في أي حقل | نفس `null` — بيتورّث |
| **حقل واحد بقيمة** — `{ "district": "الملقا" }` | **الحقل ده بس بيتغيّر**، التلاتة التانيين بيتورّثوا |

**مثال:** التصريح الحالي `{ الرياض، النرجس، 12، 3 }`، والتجديد اتبعت بـ`{ "district": "الملقا" }`
← التجديد: `{ الرياض، الملقا، 12، 3 }`.

**وبعد اعتماد التجديد**، `GET /units/{id}` بيرجّع العنوان الموروث ده في `permitAddress` — مختبَر.

### ⚠️ ده **عكس** تعديل الوحدة

| | `null` معناها |
|---|---|
| `PATCH /units/{id}` — `permitAddressCity: null` | **امسح** |
| `POST /units/{id}/permit-renewals` — `permitAddress.city: null` | **زي ما هو** |

**ده مقصود:** خانة سايبها الشريك فاضية في فورم التجديد **ماتتقريش «امسح»** — عشان مايخسرش
عنوانه من غير ما ياخد باله.

**فمافيش طريقة تمسح بيها العنوان من التجديد.** لو التصريح الجديد فعلاً مالوش حقل (مبنى مثلاً)،
الشريك يمسحه بـ`PATCH /units/{id}` بعد ما التجديد يتعتمد:

```jsonc
PATCH /units/{id}
{ "permitAddressBuilding": null }
```

### اللي بتعملوه دلوقتي

**ملّي الفورم بالعنوان الحالي: صح، ومش ضروري في نفس الوقت.** لو بعتّوه زي ما هو بيتكتب نفسه، ولو
ماتبعتوش بيتورّث — **الاتنين بيوصلوا لنفس النتيجة**. خلّوه لو بيساعد الشريك يشوف العنوان.

### استثناء واحد في نفس الطلب

**`permitExpiresAtHijri: null` بيمسح** — معناها «التاريخ ده اتكتب ميلادي». ده **الحقل الوحيد في
التجديد** اللي `null` فيه إجابة مش غياب. التفاصيل الملحق §٣.١.

```jsonc
POST /units/{id}/permit-renewals
{
  "permitExpiresAt": "2027-09-23",
  "permitAddress": { "city": null },     // ← بيتورّث
  "permitExpiresAtHijri": null           // ← بيمسح (اتكتب ميلادي)
}
```

٩ اختبارات جديدة (`PermitRenewalContractTest`)، وكل واحد **اتجرّب إنه بيقع** لو السلوك اتغيّر:

| لو حد غيّر… | اللي بيقع |
|---|---|
| خلّى التجديد يرفض الوحدات الـ`pending` | **٤ اختبارات** |
| خلّى `null` في العنوان يمسح بدل ما يورّث | **٥ اختبارات** |

**فالسلوك ده مش صدفة — لو اتغيّر، هيتغيّر بقرار ومش من غير ما حد ياخد باله.**
