## ٠. ✅ العمولة ١٠٠٪ — سيرفر، مش تعليق

```php
// Pricing::breakdown()
$commissionRate = $mamsaOwned ? 1.0 : (float) config('booking.commission_rate');
$commission     = $commissionRate >= 1.0 ? $netBase : round($netBase * $commissionRate, 2);
```

**متطبّق في الحساب نفسه**، مش وصف نية. وعند `1.0` بياخد `netBase` **كما هو** عشان `partnerShare` يبقى **صفر بالظبط** مش صفر فيه كسر تقريب — وده مهم للبند ٣.

**الاختبارات القافلة عليه:**
```
MamsaOwnedSplitTest::a_mamsa_owned_unit_keeps_the_whole_net_base
MamsaOwnedSplitTest::a_mamsa_owned_booking_credits_no_wallet
ComplaintsTest::t15_a_mamsa_owned_unit_posts_no_ledger_entry
```

## ١. ✅ `mamsaOwned` **موجود على الاتنين** — خلّوه إلزامياً

`GET /admin/approvals` و`GET /admin/approvals/{id}` بيرجّعوا **تلات إشارات** مش واحدة:

```json
{ "mamsaOwned": true, "partnerName": "ممسى", "partnerType": "mamsa" }
```

`mamsaOwned` **boolean دايماً** — `(bool) $u->mamsa_owned` — عمره ما `undefined`. **اقفلوه إلزامياً في العقد**، وسيبوا `partnerType === 'mamsa'` كإشارة تانية لو عايزين.

## ٢. 🔴 `partnerId` = **الأدمن اللي أنشأها** — قلقكم في محله بالكامل

```php
// AdminPanel\UnitsController::store()
'user_id'     => $request->user()->getKey(),
'mamsa_owned' => true,
```

وعلى الإنتاج: **الأربع وحدات مَمْسَى كلها `user_id = 14`** — «مشرف تجريبي»، دوره `SuperAdmin`.

فأيوه: **فيه صف "شريك" بيشاور على موظف.** والسؤال الصح بعدها: هل أي شاشة بتجمّع بالـ `partnerId` بتضمّه؟ فحصنا كل مكان — القسم ٦.

## ٣. ✅ المحافظ: مستبعدة فعلاً · 🟠 التقارير: **ما بتفصلش**

### المحفظة والدفتر — مستبعدة، بس بطريقة تستاهل تعرفوها

```php
// PartnerWalletService::recordEarning()
if (! $partnerId || $share <= 0 || $this->alreadyEarned($booking)) {
    return null;
}
```

**الاستبعاد حسابي مش صريح**: حجز مَمْسَى `partner_share = 0` فبيتخطّى. شغّال ومقفول باختبار، وبيعتمد على إن `Pricing` بيضمن الصفر **بالظبط** (البند ٠). فحص `mamsa_owned` صريح جنبه هيبقى belt-and-braces — **بند صغير، مش عاجل.**

**والبيانات على الإنتاج نظيفة:**
```
قيود دفتر للأدمن 14 : 0
تحويلات (payouts)    : 0
معاملات محفظة        : 0
حجوزات وحدات مَمْسَى : 2 — كلها partner_share = 0
```

### التقارير — بتجمع الاتنين في رقم واحد

`ReportsController::totalCommission` بيجمع `commission_amount` لكل الحجوزات. حجز مَمْسَى عمولته = الصافي كامل، فبيدخل **بنفس المفتاح** مع عمولة ١٠٪ من وحدة شريك.

**توصيفكم صح: إيراد المنصة من وحداتها مش نفس عمولتها من وحدات الشركاء، وجمعهم بيخفي الفرق.** بس ده **قرار تقرير** مش باج — الرقم صحيح كإجمالي، غامض كتحليل. **لو عايزين الفصل، قولوا وهو `groupBy(mamsa_owned)` في مكان واحد.**

## ٤. التصريح على وحدة مَمْسَى — 🔴 **كان بيتحذف في صمت، اتصلح**

### ٤.١ الحقلان كانوا بيتقبلوا وبيتجاهلوا

قواعد `UnitWriter` المشتركة **بتتحقق** من `licenseType` و`licensedUnitsCount` على سطح الأدمن — بس `toColumns()` **بقصد** ما بتمررهمش (أعمدة مجموعة، ليها كاتب واحد). لوحة الشريك اتوصّلت بـ `applyToGroup` لما القواعد اتضافت؛ **لوحة الأدمن لأ.**

**النتيجة: `200` ومفيش حاجة اتحفظت.** ولوحدة مَمْسَى ده كان **السطح الوحيد** اللي يقدر يحط تصريح أصلاً — يعني ولا مبنى مَمْسَى كان ممكن يتصنّف، وبالتالي ولا واحد كان ممكن يتوسّع.

**اتصلح ومنشور على staging:** `POST /admin/units` و`PATCH /admin/units/{id}` بيمرروا الحقلين للكاتب الواحد، وبيرفضوا الزوج غير المتسق بكوده (`LICENSED_UNITS_COUNT_REQUIRED`) بدل ما يقبلوه ويتجاهلوه. اختباران.

### ٤.٢ و ٤.٣ — **قرارات منتج، بس فيهم حقيقة تقنية واحدة**

مين بيملك تصريح وحدة مَمْسَى، وبأنهي ملف المراجع بيطابق — **مش قرار كود.** الكيان القانوني اللي بيصدر فواتير مَمْسَى هو **شركة إثابة المالية** (بيانات ZATCA)، فالافتراض المعقول إن تصريحها السياحي هو اللي بيغطي وحداتها. **بس ده يتقرّر مش يُستنتج.**

**والحقيقة التقنية:** وحدة مَمْسَى بتعدّي على نفس طابور المراجعة — يعني **أدمن بيراجع تقديم أدمن**. مفيش فصل مهام في الكود. على الإنتاج: وحدة #39 معتمدة **من غير رقم تصريح ولا ملف**، و`submitted_at = NULL` — يعني ما عدّتش على البوابة أصلاً.

## ٥. التوسيع — **مستحيل لوحدة مَمْسَى من أي واجهة، النهاردة**

| المسار | الحارس | الأدمن |
|---|---|---|
| `POST /api/v1/partner/units/{unit}/apartments` | `role:Individual\|Company` | **403** — دوره `SuperAdmin` |
| `POST /units/{id}/apartments` (اللوحة) | `auth:dashboard` + `ownUnit()` | **مش هيقدر يعمل login أصلاً** — `PARTNER_NOT_FOUND` |

**فالإجابة على ٥.٣: مفيش مسار.** المبنى الوحيد الموجود (على staging) اتعمل **بالكود**.

وحتى لو وُجد المسار، كان هيترفض بـ `MULTI_UNIT_REQUIRES_FACILITY_LICENSE` — لأن التصريح ما كانش بيتحفظ (٤.١). **الإصلاح ده شرط لازم مش كافي:** المسار على سطح الأدمن بند شغل منفصل، **لو المنتج قرر إن مَمْسَى بتبني مباني أصلاً.**

## ٦. 🔴 السؤال اللي قلقكم — **صح، ولقينا اتنين**

فحصنا **كل** مكان بيجمّع أو بيفلتر بمالك الوحدة (١٨ موقع) وكل مكان بيوصل لـ `->owner->` من غير null-safety (٤ مواقع).

### ✅ سليم بالبناء

- **قائمة الشركاء وترتيب أفضل الشركاء**: `User::role(['Individual','Company'])->whereHas('partnerDetail')` — الأدمن 14 **مش بيظهر** لأنه `SuperAdmin` من غير `partnerDetail`.
- **المحفظة والتحويلات**: صفر بالظبط (٣).
- **تنبيهات الشكاوى**: `if (! mamsa_owned && owner)` قبل الإشعار.
- **الإشعارات**: بتتوجّه لكل الـ `SuperAdmin` لما `mamsa_owned`.

### 🔴 الفجوة الأولى — **وكانت حية على الإنتاج**

`UnitResource` (سطح الضيف) كان بيعرض **صف الأدمن كمضيف**:

```
GET https://api.mamsaa.com/api/v1/units/34     ← إنتاج، 16/09
"owner": { "id": 14, "name": "مشرف تجريبي", "type": "individual", "is_verified": false }
```

**اسم موظف شخصي على المتجر، كمالك فردي غير موثّق، على إعلان مملوك للمنصة.** و`mamsa_owned` مش في مغلّف الضيف، فالمتجر ما كانش عنده أي طريقة يعرف.

**اتصلح:** لما `mamsa_owned`، الـ owner بيرجع `{ name: "ممسى", type: "mamsa", is_verified: true }`. وحدات الشركاء زي ما هي. اختباران في الاتجاهين.

> ⚠️ **للمتجر:** `owner.type` بقى ممكن يبقى **`"mamsa"`** جنب `individual` و`company`. لو فيه switch من غير default، ضيفوا الحالة.

## ٧. الـ ٢٪ — **المستندات اللي سمّيتوها مش في الريبو ده**

فحصنا: `BACKEND_SPEC.md` و`BACKEND-REQUEST-mamsa-owned-units.md` ومستندات الحالة اللي فيها `PLATFORM_COMMISSION_RATE = 0.02` — **مش موجودين في ريبو الباك اند.** دول في ريبو لوحة الأدمن، **اتكتبوا عندكم** من ردودنا القديمة.

**اللي في ريبو الباك اند صح:**
```
config/booking.php        commission_rate = 0.10  · LEGACY_COMMISSION_RATE = 0.02 (تاريخي، ما يتدمجش)
MAMSA-BACKEND-STATE.md    "live 0.10 · legacy 0.02"
```

**وصلّحنا الحاجة الوحيدة الغلط عندنا:** تعليق في `Analytics.php` بيقول «العمولة ٢٪ من الإجمالي» جنب كود بيقرا `commission_amount` المجمّد صح. **الكود كان صح والتعليق كذاب** — وده بالظبط النوع اللي قلتوا عليه.

**فالملكية:** المستندات دي عندكم. **توصيتنا: تتصحّح لا تتعلّم** — لأن مستند معلّم «قديم» لسه بيتقرا، وصياغة `round(total * 0.02)` هتتنسخ. ولو حد عنده شك، **المرجع الوحيد هو `config('booking.commission_rate')`** — أي رقم في مستند نسخة منه.
