# تقرير المرحلة ٤ — وضع أ: تصريح لكل شقة · حيّ على staging

**التاريخ:** 22/09/2026 · **الحالة:** ✅ staging · الإنتاج مستني كلمتكم

---

## ١. الوضعان — والمود مقروء مش مخزّن

| الوضع | التصريح | الوحدات |
|---|---|---|
| **single_permit** (ب) | تصريح **مرفق سياحي واحد** صادر للعقار | يغطي كل الأبواب · `licensed_units_count` هو السقف |
| **per_unit** (أ) | **تصريح لكل شقة**، ضيافة خاصة | كل باب بتصريحه ورقمه وملفه وتاريخه |

**المود بيتقرا من نوع التصريح اللي المجموعة شايلاه، مش من عمود جديد** — لأن ده اللي الورقة بتثبته، والعمود كان هيعيد قوله بس، ومصدران للحقيقة الواحدة هو بالظبط إزاي مجموعة بتختلف مع نفسها.

**وضع أ مش «تصريح واحد بيغطي ٥ أبواب»** — هو **٥ تصاريح بتشترك في عنوان**. وده سبب كل قاعدة تحت.

---

## ٢. العقد

```jsonc
POST /units/{id}/apartments          (الشريك)
POST /admin/units/{id}/apartments    (الأدمن، لوحدات ممسى)

// وضع ب — زي ما هو، من غير تغيير
{ "count": 5 }

// وضع أ — تصريح لكل شقة جديدة
{
  "count": 3,
  "permits": [
    { "number": "MA-2",              // ✅ إلزامي
      "fileId": "file_01m…",         // ✅ إلزامي — شوف ٢.٣
      "apartmentNo": "2",            // اختياري — لو موجود بيحدد الباب
      "expiresAt": "2027-09-22",     // اختياري · YYYY-MM-DD
      "address": { "city": "…", "district": "…", "building": "…", "unitNo": "…" } },
    { "number": "MA-3", "fileId": "file_01m…" }
  ]
}
```

**`permits.length` = عدد الشقق الجديدة، مش الإجمالي.** مبنى فيه بابان وبيروح لخمسة بيرفع **٣** تصاريح. «٣ من ٥» كانت هتبعت الشريك يدوّر على ورقتين مش محتاجهم.

**و`apartmentNo` لو موجود بيحدد الباب** — الشريك ملّى فورم لكل شقة، وأرقام الأبواب هي اللي بيفكر بيها، فترتيب الإرسال مالوش دخل.


### ٢.٢ أكواد الرفض — كلها مجرَّبة على staging

```jsonc
// وضع أ من غير تصاريح
{ "error": { "code": "PERMIT_MODE_MIXED",
             "message": "كل وحدة في هذا المبنى تحتاج تصريحها الخاص — أرسل تصريحاً لكل وحدة جديدة",
             "meta": { "group_mode": "per_unit" } } }                      // 422

// وضع ب ومعاه تصاريح
{ "error": { "code": "PERMIT_MODE_MIXED",
             "message": "هذا المبنى تحت تصريح واحد يغطي كل الوحدات — لا تُرسل تصاريح منفصلة",
             "meta": { "group_mode": "single_permit" } } }                  // 422

// العدد غلط
{ "error": { "code": "PERMITS_COUNT_MISMATCH",
             "message": "عدد التصاريح المرسلة لا يساوي عدد الوحدات الجديدة",
             "meta": { "requested": 2, "permits_provided": 1 } } }          // 422

// رقم مستخدم في وحدة تانية
{ "error": { "code": "DUPLICATE_PERMIT_NUMBER",
             "message": "رقم التصريح مستخدم بالفعل في وحدة أخرى",
             "meta": { "permit_number": "TL-TEST-0002", "claimed_by_unit_id": 13 } } }   // 422

// نفس الرقم مرتين جوّه نفس الطلب — من غير claimed_by_unit_id
{ "error": { "code": "DUPLICATE_PERMIT_NUMBER",
             "message": "رقم التصريح مكرر داخل الطلب نفسه",
             "meta": { "permit_number": "SAME-1" } } }                       // 422

// وحدة غير مصنّفة
{ "error": { "code": "MULTI_UNIT_REQUIRES_FACILITY_LICENSE",
             "message": "صنّف تصريح الوحدة أولاً قبل إضافة وحدات",
             "meta": { "license_type": null, "max_units": 1 } } }            // 422

// ملف مش بتاع الشريك / مش مرفوع فعلاً
{ "error": { "code": "VALIDATION", "message": "ملفات غير صالحة",
             "fields": { "permits.0.fileId": "ملف الرخصة غير موجود" } } }    // 400 (الشريك) · 422 VALIDATION_ERROR (الأدمن)
```

**ترتيب الفحوصات** (مهم للواجهة عشان ما تتفاجأش):
```
1. الشكل يطابق المود        → PERMIT_MODE_MIXED
2. كل ملف تصريح ملك الشريك  → VALIDATION (fields)
3. التصريح يغطي الحجم       → MULTI_UNIT_REQUIRES_FACILITY_LICENSE / QUANTITY_EXCEEDS_LICENSED_UNITS
4. الوحدة الأصل مكتملة      → SOURCE_UNIT_INCOMPLETE
5. عدد التصاريح             → PERMITS_COUNT_MISMATCH
6. تفرّد الأرقام            → DUPLICATE_PERMIT_NUMBER
```

### ٢.٣ 🔴 `fileId` إلزامي في وضع أ — وده مقصود

في وضع أ **مفيش حاجة بتتنسخ** على الشقق الجديدة، فشقة جاية من غير ملف تصريحها **مستحيل تتنشر** — بوابة الإرسال بترفضها. لو سبناه اختياري، كان الرفض هيحصل **بعد** إنشاء الصفوف وبيرجّع العملية كلها برسالة عن صف الشريك ما شافهوش.

**يعني في الويزارد: رفع ملف لكل شقة، مش ملف واحد.**

---

## ٣. القواعد اللي اتفرضت

1. **المجموعة ليها مود واحد** — الخلط مرفوض، مش بيتحل بالتخمين.
2. **مفيش نسخ في وضع أ** — نسخ تصريح شقة على جيرانها هو بالظبط اللي التصريح الخاص ما بيعملهوش.
3. **نشر باب في وضع أ بيتطلب تصريحه هو** — تصاريح جيرانه بتسمّي شقق تانية، فباب بلا تصريح مغطّى بلا حاجة. `PERMIT_MODE_MIXED` عند الاعتماد لو حصل.
4. **التفرّد: رقم واحد، نطاق واحد.**
5. **المسار القديم `/api/v1/partner` بيرفض وضع أ صراحة** — ما عندوش طريقة يحمل تصريح لكل شقة، فكان هيعمل شقق مغطّاة بلا حاجة. متقاعد أصلاً، بس الحارس موجود عشان مسار الرجوع ما يبقاش ثغرة.

### ٣.١ ليه التفرّد مش `UNIQUE` في قاعدة البيانات

**لأن في وضع ب نفس الرقم بيقعد على صف لكل باب بشكل مشروع** — مبنى بـ٨ شقق بيحمل الرقم ٨ مرات على `units` وصف واحد في `permits`. فاللي لازم يبقى فريد مش «الرقم» بل **النطاق اللي بيدّعيه**: صف `permits` واحد لكل رقم. بيتفرض في الكاتب **جوّه الـtransaction بعد القفل** — لأن طلبين بيقروا «فاضي» ويكتبوا هو السباق اللي الفحص برّه القفل ما بيشوفهوش — ومعاه الفحص اليومي كشبكة تانية.

### ٣.٢ الاستثناء المسجّل
`PERMIT_UNIQUENESS_EXCEPTIONS` في الـenv، قيمته الافتراضية `50047139` — تصريح `#35`/`#37` على الإنتاج. **مسجّل مش متخطّى**: الفحص اليومي ما بيشتكيش منه، وأي تكرار تاني بيتبلّغ. لما المالك يحسم `#37`، شيل الرقم من الـenv — **من غير نشر كود**.

## ٤. 🟠 حاجة ظهرت على staging وإنتوا محتاجين تعرفوها

**بيانات staging فيها أرقام تصاريح مكررة من البذور**، والقاعدة الجديدة بتمنع أي تعديل على تصريح الوحدات دي:

```
TL-TEST-0001 → الوحدتان 12 و24     (اتحلّت — #24 بقى رقمها TL-MODE-A-24)
TL-TEST-0002 → الوحدتان 13 و25     ← لسه قائمة
```

اكتشفناها لأن **محاولة إرجاع بيانات الاختبار لحالتها بعد التجربة اترفضت**: `TL-TEST-0001` بقى مستحيل يترجع على `#24` لأن `#12` شايله.

**فـ`#24` على staging دلوقتي رقمها `TL-MODE-A-24` بدل `TL-TEST-0001`** — غير مصنّفة، معتمدة، بلا مجموعة، زي ما كانت في كل حاجة تانية.

**محتاجين قراركم في `TL-TEST-0002` (الوحدتان 13 و25):** يا نغيّر رقم واحدة فيهم، يا نضيفه لاستثناءات staging. لحد ما يتحل، **أي تعديل تصريح على `#13` أو `#25` هيترفض** بـ`DUPLICATE_PERMIT_NUMBER`.

ونفس الشكل هيحصل على الإنتاج لو ظهر تكرار جديد — عشان كده الاستثناء موجود كـenv.

## ٥. 🔴 باج لقيناه واتصلح — يستاهل يتقال

أول تشغيل لوضع أ طلع مبنى بتلات أبواب و**تصريح واحد** رقمه آخر رقم اتكتب، منسوخ على الكل.

السبب: `Permit::scopeOf()` كانت بتقرر النطاق من **التجميع** (عنده `unit_group_id`؟ يبقى نطاق مجموعة) بدل **نوع التصريح**. فتصريح الشقة التانية **عدّل صف** الشقة الأولى بدل ما يعمل صفه، وتصاريح الشقق الأولى راحت.

**الإصلاح:** النطاق بيتبع نوع التصريح — تصريح مرفق صادر للعقار فنطاقه المجموعة، وتصريح خاص بيسمّي شقة فنطاقه الشقة حتى جوّه مبنى. **اختبار بيغطيه، واتأكدنا إنه بيفشل تاني بالنطاق القديم.**
