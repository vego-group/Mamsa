# عقد تطبيق الضيف — الشكاوى

**التاريخ:** 06/09/2026
**المستودع:** `vego-group/mamsa-frontend`
**البيئة:** `https://staging.mamsaa.com/api/v1` — **بادئة `/api/v1`** · Bearer / Sanctum
**الحالة:** المسارات حيّة على staging

> ⚠️ **الترميز هنا `snake_case`**، مش camelCase زي لوحتي الأدمن والشريك. ده اتفاق `/api/v1` القائم من قبل الشكاوى، وسيبناه على حاله عشان ما نخلقش استثناء في سطح كامل.

---

## 1. تقديم شكوى

```
POST /api/v1/bookings/{booking}/complaint      Content-Type: multipart/form-data
```

### الحقول

| الحقل | النوع | القيد |
|---|---|---|
| `description` | string | **مطلوب** · 20–2000 حرف |
| `contacted_partner` | boolean | **مطلوب** |
| `images[]` | file | اختياري · **0–6 صور** · **5 ميجابايت** للصورة · `image/jpeg` \| `image/png` \| `image/webp` فقط |

`throttle:6,1` على المسار — ٦ محاولات في الدقيقة.

### الرد `201`

```json
{ "id": 12, "status": "submitted", "created_at": "2026-09-06T14:22:00+00:00" }
```

### أكواد الرفض — **جديدة، أضيفت من أجل هذا العقد**

كل رفض بيرجّع `code` ثابت جنب الرسالة. **افرعوا على `code` مش على `message`** — الرسالة عربية وقابلة للتحسين، والكود مش هيتغير.

```json
{ "success": false, "code": "WINDOW_CLOSED", "message": "انتهت مهلة تقديم الشكوى (48 ساعة بعد انتهاء الإقامة)" }
```

| HTTP | `code` | الحالة |
|---|---|---|
| 403 | `NOT_YOUR_BOOKING` | الحجز مش بتاع المستخدم الحالي |
| 422 | `BOOKING_NOT_COMPLETED` | الحجز مش `completed` |
| 422 | `WINDOW_NOT_OPEN` | لسه قبل بداية الإقامة |
| 422 | `WINDOW_CLOSED` | عدّت 48 ساعة على انتهاء الإقامة |
| 409 | `COMPLAINT_ALREADY_EXISTS` | فيه شكوى على الحجز ده بالفعل |
| 404 | `NO_COMPLAINT` | (على `GET`) مفيش شكوى على الحجز |
| 422 | — | فشل تحقق عادي — الرسائل في `errors` بالشكل المعتاد |

**النافذة الزمنية**، بتوقيت **`Asia/Riyadh`** صراحةً — مش بتوقيت الخادم:

```
تفتح:  00:00 من يوم بداية الإقامة
تقفل:  وقت مغادرة الوحدة (units.checkout_time) + 48 ساعة
```

يعني وحدة مغادرتها 12:00 وإقامة انتهت 15/09 → النافذة تقفل **17/09 الساعة 12:00**.

⚠️ **مش من منتصف الليل.** الحساب من منتصف ليلة المغادرة كان بيدي الضيف **36 ساعة** بدل 48، والنقص بيكبر كل ما وقت المغادرة يتأخر.

**وحدة من غير `checkout_time` مسجّل** بتتحسب على **12:00** — مش 00:00. نقص البيانات عندنا مش سبب لتقصير مهلة الضيف؛ ٢٦ من ٣٢ وحدة عليها 12:00 فعلاً وهي القيمة المعلنة في الوثائق.

## 2. قراءة الشكوى

```
GET /api/v1/bookings/{booking}/complaint
```

```ts
type GuestComplaint = {
  id: number
  status: 'submitted' | 'under_review' | 'approved' | 'resolved_refunded' | 'resolved_rejected'
  description: string
  contacted_partner: boolean
  guest_message: string | null      // نص القرار، من الأدمن
  refunded_amount: number | null    // بالريال (مش هللات) — اقرأ الشرح
  created_at: string | null
  images: Array<{ url: string; mime: string }>
}
```

مغلّف بالشكل المعتاد: `{ success, message, data }`.

### `refunded_amount` — إمتى بيظهر

**بعد التسوية بس.** الحقل بيتملّي من صف `refunds` حالته `succeeded` فقط.

ده تأكيد للي اتفقنا عليه: الضيف **مايشوفش رقم** قبل ما الفلوس تتحرك فعلاً. الاسترداد ممكن يفضل `pending` عند البوابة لساعة أو أكتر، وممكن يفشل. لو التطبيق عرض مبلغ في اللحظة دي والاسترداد فشل، بنكون وعدنا بفلوس ما وصلتش.

⚠️ **بالريال، مش بالهللات** — بعكس سطح الأدمن. ده اتفاق `/api/v1` القائم.

### `guest_message`

بيظهر لما الأدمن ياخد قرار (قبول أو رفض). قبل كده `null`. **ده النص الوحيد الموجّه للضيف** — `internal_note` بتاع الأدمن مش في الرد ولا هيبقى.

## 3. قائمة شكاوى المستخدم

```
GET /api/v1/user/complaints
```

⚠️ **المسار `/user/complaints` مش `/me/complaints`.** الـ `/me` على الجذر محجوز لجلسة الشريك، فحطها هنا كان هيصطدم بيها.

```ts
type GuestComplaintRow = {
  id: number
  status: GuestComplaint['status']
  booking_id: number
  booking_code: string | null
  created_at: string | null
}
```

## 4. المرفقات

**نفس الروابط الموقّعة**، أيوة — ونفس القاعدة: **صلاحيتها ١٥ دقيقة**.

بتتولد وقت قراءة التفاصيل، مش وقت الرفع. يعني الضيف لو فتح شكواه بعد أسبوع بياخد روابط جديدة صالحة ١٥ دقيقة من اللحظة دي.

**لا تخزّنوها.** لو الشاشة فضلت مفتوحة والصور وقفت تظهر، أعيدوا جلب التفاصيل — مش علامة على خطأ.

الصور على قرص خاص مش عام؛ مفيش رابط دائم لأي مرفق في النظام.

## 5. الحالات — إيه اللي الضيف يشوفه

| الحالة | المعنى للضيف |
|---|---|
| `submitted` | وصلت، لسه ما اتراجعتش |
| `under_review` | تحت المراجعة — والضيف بياخد SMS عند الانتقال دي |
| `approved` | اتقبلت، **والاسترداد جارٍ** — SMS من غير مبلغ ومن غير مدة |
| `resolved_refunded` | تم — SMS + إيميل **بالمبلغ**، و`refunded_amount` بيبقى فيه رقم |
| `resolved_rejected` | مارفضتش لصالحه — SMS، و`guest_message` فيه السبب |

⚠️ **`approved` مش «تم الاسترداد».** الرسالة اللي بتروح للضيف في الحالة دي متعمدة إنها من غير مبلغ ومن غير توقيت — لأن الاسترداد لسه ممكن يفشل. التطبيق لازم يمشي على نفس المبدأ: **مفيش رقم قبل `resolved_refunded`.**

## 6. ملاحظات

- الرسائل عربية جاهزة للعرض — ما تترجموهاش
- التواريخ ISO-8601 → اعرضوها `DD/MM/YYYY` بتوقيت الرياض
- العملة **ريال سعودي فقط**
- **الشكوى واحدة لكل حجز** — لا تعديل ولا سحب. المسار الوحيد للتعديل هو التواصل مع الدعم
- **ممنوع حساب أي تقسيم في التطبيق.** المبلغ اللي الضيف يشوفه هو `refunded_amount` كما جاء
