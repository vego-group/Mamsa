# كارت تاريخه منتهي في وضع أ — **`fields.permitExpiresAt` من غير رقم الكارت**

**التاريخ:** 30/09/2026
**لمين:** فريق Next.js — لوحة الشريك
**الحالة:** ده سلوك الكود من الأول — **مافيش تغيير في الـAPI.** اللي اتصلح هو دليل البناء بتاعنا.

---

## ١. الخلاصة

1. **المفتاح الصح: `fields.permitExpiresAt`** — **مش** `fields["permits.0.expiresAt"]`. **من غير رقم كارت
   ومن غير `meta`.**
2. **الملحق (§١.٢) كان صح. دليل البناء (§٨.٨) هو اللي غلط** — وعد إن الخطأ «بيوصل الكارت الصح»، وده
   مش ممكن من الرد. **الغلط عندنا، واتصلح.**
3. **الـfallback بتاعكم (الخطأ على الكارت اللي تاريخه فات) صح وكامل — بشرط:** المقارنة **بتوقيت الرياض**،
   مش بتوقيت جهاز الشريك.

---

## ٢. الرد بالظبط

جرّبناه بـ٣ كروت، والتاريخ المنتهي على **الكارت اللي في النص** — عشان يبان إن الرد مابيحددش أنهي كارت:

```jsonc
POST /units/{id}/submit        { "count": 4, "permits": [ ✅, ❌ منتهي, ✅ ] }
POST /units/{id}/apartments    { "count": 4, "permits": [ ✅, ❌ منتهي, ✅ ] }

// الاتنين:
400 {
  "error": {
    "code": "VALIDATION",
    "message": "بيانات غير مكتملة",
    "fields": { "permitExpiresAt": "تصريح الوحدة منتهي — جدّده قبل الإرسال للمراجعة" }
  }
}
```

| | |
|---|---|
| رقم الكارت في المفتاح | **مفيش** |
| `meta` | **مفيش** |
| اللي اتخلق | **ولا حاجة** — الوحدة `draft` وصفر شقق |

**ليه مافيش رقم:** الفحص ده بيتعمل على كل شقة **بعد** ما بتتخلق — نفس فحص الإرسال العادي — فالسيرفر
ساعتها مابيبقاش عارف الشقة دي جت من أنهي كارت.

---

## ٣. إزاي تحددوا الكارت — **بتوقيت الرياض**

**قاعدة السيرفر:** التاريخ منتهي لو **أقدم من النهارده بتوقيت الرياض** (`Asia/Riyadh`).
التصريح اللي بينتهي **النهارده** لسه صالح لحد منتصف الليل بتوقيت الرياض.

**الإنتاج وstaging الاتنين على `Asia/Riyadh`** — متأكدين منها.

```ts
// نفس شرط السيرفر بالظبط
const todayRiyadh = new Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Riyadh' }).format(new Date()) // "YYYY-MM-DD"
const expiredCards = permits
  .map((p, i) => ({ i, expiresAt: p.expiresAt }))
  .filter(p => p.expiresAt && p.expiresAt < todayRiyadh)   // مقارنة نصوص YYYY-MM-DD
```

**لو قارنتوا بـ`new Date()` العادي (توقيت الجهاز):** شريك برّه السعودية، أو جهاز ساعته غلط، هيختلف
مع السيرفر — **في حالة منتصف الليل بالظبط** اللي بتسألوا عنها. السيرفر يقول منتهي، والواجهة ماتلاقيش
ولا كارت تاريخه فات، والخطأ مايلاقيش مكان يتحط فيه.

**بالمقارنة بتوقيت الرياض، الكروت اللي هتطلع = بالظبط الكروت اللي السيرفر بيرفضها.**

لو طلع أكتر من كارت منتهي، حطّوا الخطأ على كلهم — كلهم هيترفضوا.

---

## ٤. باقي أخطاء الكارت — **ليها رقمها**

التاريخ هو **الحقل الوحيد** في الكارت اللي خطؤه من غير رقم:

| خطأ الكارت | الرد | بيحدد الكارت؟ |
|---|---|---|
| الملف | `400 VALIDATION` · `fields["permits.{i}.fileId"]` | ✅ بالرقم |
| رقم تصريح مكرر | `422 DUPLICATE_PERMIT_NUMBER` · `meta.permit_number` | ✅ بالرقم نفسه |
| الهجري من غير ميلادي | `400 VALIDATION` · `fields["permits.{i}.expiresAtHijri"]` | ✅ بالرقم |
| **التاريخ منتهي** | `400 VALIDATION` · **`fields.permitExpiresAt`** | ❌ — **حددوه بتوقيت الرياض (§٣)** |

---

## ٥. اللي اتصلح عندنا

**دليل البناء §٨.٨، الاختبار ٥** كان بيقول:

> ~~«`fields.permitExpiresAt` بيوصل الكارت الصح»~~

**بقى:**

> الـAPI بيرجّع `400 VALIDATION` · `fields.permitExpiresAt` — **من غير رقم الكارت**. الواجهة بتحدد
> الكارت: كل كارت `expiresAt` بتاعه أقدم من النهارده **بتوقيت الرياض**.

**والملحق §١.٢** اتزاد فيه نفس التوضيح جنب السطر.

**مافيش اختبار جديد:** فيه اختبار موجود أصلاً (`ApartmentModeTest`) بيثبّت نفس الرد ده على `/submit`
بكارتين والتاني منتهي — ومعاه إن مافيش ولا شقة اتخلقت.

---

## ٦. لو عايزين رقم الكارت صريح

نقدر نخلّي الـAPI يرجّع **`fields["permits.{i}.expiresAt"]` جنب المفتاح الحالي** — من غير ما حاجة
تتكسر. تغيير صغير، **بس تغيير عقد** — فالقرار عند المالك.

**مع قاعدة توقيت الرياض فوق، مش ضروري** — النتيجة هي هي.
