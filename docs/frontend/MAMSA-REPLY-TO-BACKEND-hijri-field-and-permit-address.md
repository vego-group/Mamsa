## ٢. `permitAddress` — **موجود دايماً**

```jsonc
GET /units/{id}      ·      GET /units   (كل صف في data)

"permitAddress": { "city": null, "district": null, "building": null, "unitNo": null }
```

| السؤال | الإجابة |
|---|---|
| المفتاح موجود لو الوحدة مالهاش تصريح خالص؟ | **أيوه** |
| ممكن يرجع `null` لوحده؟ | **لأ** — دايماً object |
| الأربع مفاتيح دايماً موجودين؟ | **أيوه** — كل واحد `null` لو مش متسجّل |

ده مقصود في الكود من الأول، **ومن 30/09 عليه اختبار** بيثبته على وحدة مالهاش تصريح — في العرض
المفرد وفي القايمة. **واتحقّقنا منه بنداء حقيقي على staging.**

**فتقدروا تقروا `permitAddress.city` على طول** من غير `?.` على `permitAddress` نفسه.

> عينة §٢.١ في ملف المراحل ١–٣ كانت ناقصاه لأن اللقطة اتاخدت قبل ما يدخل الرد. **اتصلحت**،

## ٤. `permitExpiresAtHijri` — الهجري **زي ما اتكتب**

### ليه

الـAPI بيخزّن الميلادي بس، والتحويل عندكم. لو جدول الوزارة طلع مختلف عن مكتبتكم، التواريخ
المخزّنة كلها غلط بيوم **ومافيش أصل نعيد منه**. دلوقتي الأصل بيتخزّن.

### فين بيتبعت

| المسار | المفتاح |
|---|---|
| `POST /units` · `PATCH /units/{id}` | `permitExpiresAtHijri` |
| `POST /admin/units` · `PATCH /admin/units/{id}` | `permitExpiresAtHijri` |
| `POST /units/{id}/permit-renewals` | `permitExpiresAtHijri` |
| `POST /units/{id}/apartments` · `POST /admin/units/{id}/apartments` | `permits.*.expiresAtHijri` |

```jsonc
{
  "permitExpiresAt": "2027-09-23",         // اللي الـAPI بيحسب عليه — زي ما هو
  "permitExpiresAtHijri": "٢٢/٠٤/١٤٤٩ هـ"   // اختياري · نص ≤ 50 · بيتخزّن حرفياً
}
```

### القواعد

- **اختياري بالكامل.** مافيش حاجة بتتكسر لو ماوصلش.
- **ابعتوه زي ما الشريك كتبه بالظبط** — ماتنضّفوهوش ولا توحّدوا الأرقام. الـAPI بيخزّنه **حرف بحرف**،
  ومستثنيه حتى من قصّ المسافات اللي الإطار بيعمله على كل المدخلات.
- **لو الشريك كتب ميلادي مباشرة، ماتبعتوش الحقل** (أو ابعتوه `null`). الـ`null` معلومة: التاريخ ده
  مالوش أصل هجري.
- **مابيدخلش في أي حساب.** الانتهاء والتذكيرات ومنع الحجز كلها على `permitExpiresAt` بس.
- **ماتبعتوش اسم المكتبة أو نسختها** — مش بيتخزّنوا في الصف. مكانهم الورقة عندكم
  (`docs/audit/hijri-converter-pinned.md`).

### ماينفعش من غير الميلادي جنبه

الـAPI مابيحوّلش، فهجري لوحده مالوش معنى:

| السطح | الرد |
|---|---|
| لوحة الشريك | **400** `VALIDATION` · `error.fields.permitExpiresAtHijri` |
| الأدمن | **422** `VALIDATION_ERROR` · `fields.permitExpiresAtHijri` |
| الشقق | `fields["permits.0.expiresAtHijri"]` |

### 🔴 إمتى الهجري المخزّن بيفضل وإمتى بيتمسح

| اللي بتبعتوه | اللي بيحصل للهجري المخزّن |
|---|---|
| `permitExpiresAtHijri` (نص أو `null`) | **بيتخزّن زي ما اتبعت** |
| **تاريخ جديد من غير هجري** | **بيتمسح** — الهجري القديم مش أصل التاريخ الجديد |
| **نفس** التاريخ من غير هجري | **بيفضل** — عشان الويزارد اللي بيعيد إرسال كل الحقول مايمسحوش |
| حقل تاني بس (العنوان، الرقم) | بيفضل |
| **تجديد** بتاريخ جديد من غير هجري | **`null` على التجديد** — مش موروث من التصريح القديم |

**يعني عملياً:** لو الشريك عدّل التاريخ بالهجري، ابعتوا الاتنين مع بعض. لو عدّله بالميلادي، ابعتوا
الميلادي بس — والقديم هيتمسح لوحده.

### القراءة

**بنفس الاسم جنب `permitExpiresAt`** — وموجود دايماً، `null` لو مافيش:

| المسار | المفتاح |
|---|---|
| `GET /units` · `GET /units/{id}` | `permitExpiresAtHijri` |
| `GET /units/{id}/permit-renewals` + رد إنشاء التجديد | `permitExpiresAtHijri` |
| `GET /admin/units/{id}` · `GET /admin/permits` | `permitExpiresAtHijri` |
| `GET /admin/permit-renewals` | `currentPermit.permitExpiresAtHijri` |
| `GET /admin/approvals/{id}` | `permit.expiresAtHijri` · `apartments[].permitExpiresAtHijri` |

**الضيف (`/api/v1`) مابيشوفوش.**

**للمراجع في لوحة الأدمن:** لو فيه هجري، اعرضوه جنب الميلادي — ده اللي المراجع يقارنه بالورقة مباشرة.

### متحقَّق على staging بنداءات حقيقية

بحساب الشريك الاختباري (`555000002`)، على MySQL:

| الطلب | النتيجة |
|---|---|
| إنشاء بـ`" ٢٢/٠٤/١٤٤٩ هـ "` (بمسافات) | اترجع زي ما هو · **البايتات المخزّنة مطابقة حرف بحرف** |
| نفس التاريخ + حقل تاني | الهجري **فضل** |
| حقل تصريح تاني بس | الهجري **فضل** |
| هجري من غير ميلادي | **400** `VALIDATION` |
| تاريخ جديد من غير هجري | الهجري **اتمسح** |
| تاريخ + هجري مع بعض | **اتخزّن** |
| `null` صريح، نفس التاريخ | **اتمسح** |

وحدة الاختبار اتمسحت بعدها، والجلسة اتقفلت.

## ٦. حاجتين ممكن تقابلوهم على staging

### `DUPLICATE_PERMIT_NUMBER` بـ`claimed_by_unit_id: null`

**عيب قديم مش من التعديل ده:** لما وحدة تتمسح، صف التصريح بتاعها بيفضل، وفحص التفرّد لسه بيعدّه.
فلو شريك مسح مسوّدة وعمل واحدة جديدة **بنفس رقم التصريح**:

```json
422 { "error": { "code": "DUPLICATE_PERMIT_NUMBER",
                 "message": "رقم التصريح مستخدم بالفعل في وحدة أخرى",
                 "meta": { "permit_number": "…", "claimed_by_unit_id": null } } }
```

**`claimed_by_unit_id: null` هي العلامة** — «مستخدم في وحدة» ومافيش وحدة. على staging فيه رقم
واحد محجوز كده دلوقتي: **`SUI-386573`** (من وحدة 72 اللي اتمسحت). **على الإنتاج: صفر.**

لو قابلتوه وأنتوا بتختبروا، ده السبب — مش غلط عندكم. **لسه ماتصلحش**؛ القرار عند المالك.

### staging اتحدّث بالكامل النهارده

staging كان ناقصه إصلاح في مسار الاسترداد نزل على الإنتاج 22/09. اتحدّث النهارده، فبقى مطابق
للفرع. **لو شايفين سلوك مختلف في الاسترداد بعد دفع متأخر على staging من النهارده، ده السبب** — وده
دلوقتي نفس سلوك الإنتاج.
