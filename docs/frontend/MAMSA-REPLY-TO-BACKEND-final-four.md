## ١. 🔴 `meta` — **كانت بتتحذف قبل ما توصلكم · اتصلحت**

سؤالكم «`error.meta` ولا `error.licensed_units_count` ولا حاجة تانية؟» **الإجابة كانت: ولا واحدة منهم — الرقم مكانش بيتبعت أصلاً.**

المسار كان بيرفع الرفض كده:

```php
$this->fail($e->reason, $e->getMessage(), 422);   // ← e->meta اتسابت
```

و`fail()` **مكانش فيها بارامتر لـ `meta`** أصلاً. فالرفض كان بيوصلكم بكود ورسالة **وخلاص** — والشاشة كانت هتعرض `undefined` بدل الرقم.

**الغرض كله من إن الرفض يبقى قابل للقراءة آلياً كان بيضيع على بُعد بارامتر واحد من المغلّف.** سؤالكم هو اللي مسكه.

### ✅ الشكل النهائي — **`error.meta`**، ومنشور على staging

نسخة لصق من الخادم، مش مثال مكتوب بالإيد:

```json
{
  "error": {
    "code": "QUANTITY_EXCEEDS_LICENSED_UNITS",
    "message": "العدد المطلوب أكبر من عدد الوحدات المرخّصة في التصريح",
    "meta": { "requested": 9, "licensed_units_count": 8 }
  }
}
```

```json
{
  "error": {
    "code": "MULTI_UNIT_REQUIRES_FACILITY_LICENSE",
    "message": "أكثر من وحدة يتطلب تصريح مرفق ضيافة سياحي",
    "meta": { "license_type": "private_hospitality", "max_units": 1 }
  }
}
```

**المسار: `error.meta.licensed_units_count`.**

### وقاعدتان على `meta`

1. **بتتشال خالص لو فاضية** — مش `{}`. فالوجود نفسه معناه «فيه أرقام هنا»، والواجهة ما تتفرّعش على مفتاح مالوش معنى.
2. **`meta` غير `fields`** — `fields` بيقول أنهي إدخال غلط (بييجي مع `400 VALIDATION`)، و`meta` بيقول شكل الدنيا. **الاتنين ممكن يظهروا، وما بيحلّوش محل بعض.**

**فيه اختبار على المسار ده دلوقتي** — لو اتحذفت تاني، السويت بتفشل مش الشاشة.

## ٢. ✅ الشقق الجديدة **`draft`** مش `approved` — **والمراجعة بوابة فعلية**

### أولاً: المثال بتاعنا كان مضلّل، آسفين

في رد سابق كتبنا `{ "id": "u_30", "status": "approved" }` كسطر وحيد. **`u_30` هي الوحدة الأصلية** — اللي كانت معتمدة من قبل. الشقق **الجديدة** بترجع `status: "draft"`.

الرد بيحتوي على الاتنين معاً عشان ده الواقع:

```json
"units": [
  { "id": "u_30", "apartmentNo": "401", "status": "approved" },   ← الأصلية
  { "id": "u_43", "apartmentNo": "406", "status": "draft"    },   ← جديدة
  { "id": "u_44", "apartmentNo": "407", "status": "draft"    }
]
```

**فنص رسالة النجاح:** الشقق الجديدة **مش** «قيد المراجعة» — هي **مسودات لسه ما اتقدمتش**. وده مختلف، وشرحه في البند ٦ من رد الإقفال: كل واحدة محتاجة `POST /units/{id}/submit`.

### ثانياً: سؤالكم الأكبر — **لأ، مفيش شقة بتتباع من غير مراجعة**

قلقكم: «شريك كتب ٥٠ واتعمد عليه مرة، يوسّع لـ ٥٠ من غير ما حد يبص تاني».

**فحصنا التلات بوابات، والتلاتة بيستبعدوا `draft`:**

| البوابة | الشرط |
|---|---|
| البحث (`GET /units`) | `approval_status = 'approved'` |
| عدّاد التوفر (`freeCount` / `attachCounts`) | `approval_status = 'approved'` |
| تخصيص الحجز (`POST /bookings`) | `approval_status = 'approved'` |

**فالشقة المسودة مش بتظهر، مش بتتحسب، ومش بتتحجز.**

يعني `licensed_units_count` بيحدد **كام شقة ممكن توجد**، والمراجع بيحدد **كام شقة تتباع**. الرقم المُدخل بيتراجع بشرياً أول مرة، وكل شقة بتتعمل بعده لسه محتاجة اعتماد منفصل.

**فالإجابة: مقصود، والمراجعة الأولى مش البوابة الوحيدة — كل شقة بوابة لوحدها.**

**واختبار جديد بيثبّت ده:** توسيع لـ ٤ على مبنى معتمد فيه واحدة → تلات مسودات، **والمبنى لسه بيعلن `available_count: 1`** مش ٤.

## ٣. ✅ التقليص — **مجاوب في رد الإقفال · مفيش مسار · الرسالة اتصلحت**

**مفيش تقليص. خالص.** التلات احتمالات اللي سألتوا عنها:

| | النتيجة |
|---|---|
| `{count: 3}` على مبنى فيه ٨ | **بيتجاهل** — مش بيحذف ومش بيرفض. `ensureTotal` بترجع من غير ما تعمل حاجة ✅ آمن |
| `DELETE /units/{id}` (اللوحة) | **مسودات بس** → `UNIT_NOT_DELETABLE` · وكل شقة في مبنى معتمد مش مسودة |
| `DELETE /api/v1/partner/units/{id}` | بيحذف لو مفيش حجوزات نشطة — **مش على سطح اللوحة** |

**والرسالة اتغيّرت ومنشورة** — مابقتش بتقول «قلّل الوحدات أولاً»:

```json
{ "error": {
    "code": "LICENSE_DOWNGRADE_BLOCKED_BY_QUANTITY",
    "message": "هذا الإعلان مبنى متعدد الوحدات، ولا يمكن تحويله إلى تصريح ضيافة خاصة. تواصل مع الدعم لتعديل عدد وحدات المبنى.",
    "meta": { "group_size": 8, "shrink_supported": false }
} }
```

**`shrink_supported: false`** — اتفرّعوا عليها مش على النص. لما التقليص يتعمل تبقى `true`.

> **وحلّكم المؤقت («تواصل مع الدعم» لأي رقم أقل) هو الصح دلوقتي**، وبقى متسق مع رسالة الخادم.

## ٤. 🟠 `MULTI_UNIT_ENABLED` — **مفتوح على الاتنين، بما فيهم الإنتاج**

الحالة الفعلية مش المقصودة، زي ما طلبتوا:

```
staging  : المتغيّر مش موجود في .env  →  الافتراضي true  →  مفتوح ✅ (اختباراتكم هتشتغل)
الإنتاج  : المتغيّر مش موجود في .env  →  الافتراضي true  →  مفتوح ⚠️
```

**فرأيكم إنه يفضل مقفول على الإنتاج مش متحقق.** الأثر العملي محدود — المسار على سطح اللوحة منشور على staging بس، ومفيش أي مجموعة على الإنتاج — **بس نداء `/api/v1` بـ Bearer على الإنتاج هيعدّي.**

**تغيير متغيّر بيئة على الإنتاج بيتطلب موافقة مالك المنتج، والبند مرفوع مع باقي بنود الإنتاج.**

## ٥. ✅ سطح الضيف — **التأكيدان صح · مفيش تذكرة تالتة**

| # | السؤال | الإجابة |
|---|---|---|
| ١ | مبنى ٥ شقق = بطاقة واحدة؟ | ✅ **أيوه** |
| ٢ | كل الشقق محجوزة = بيختفي؟ | ✅ **أيوه — بيختفي، مش بيظهر بصفر** |

متحقق حي على staging: **١٦ وحدة رجعت · ١٦ `listing_id` مختلف · مفيش مبنى اتكرر**، والمبنى ظهر مرة واحدة بـ `available_count: 5`.

**والتاني اتضاف كاختبار:** مبنى كل شققه محجوزة **مش بيظهر في النتايج**، **وبيرجع يظهر** لما التواريخ تتشال — لأن السؤال بيتغيّر من «فاضي في الليالي دي» لـ«موجود».

**تطبيق الضيف مش محتاج ولا تذكرة.**
